## 1. Positioning & design philosophy

Kimi Code's bet is a **DI × scope-tiered agent engine as a product family kernel**, not a single CLI. `packages/agent-core-v2` is a dependency-injection engine with four `LifecycleScope` tiers (`App`/`Workspace`/`Session`/`Agent`, `app/scopes.ts`) plus a `Service`/`Fiber` unit layer and a `Feature` contribution seam; the same engine is exposed through a Node SDK (`packages/node-sdk`), a contract-driven client SDK (`packages/klient`, `global.*`/`session(id).*`/`agent(id).*`), a REST+WebSocket server (`packages/kap-server`), an ACP server (`packages/acp-server`), and the interactive TUI (`apps/kimi-code`) (FACT, src: packages/agent-core-v2/src/app/scopes.ts, packages/kap-server/, packages/klient/, packages/acp-server/ @486dcd2). The second bet is **execution-environment abstraction**: `packages/kaos` ("Kimi Agent Operating System") defines a `Kaos` interface over filesystem and process operations with both a local implementation and a full SSH/SFTP implementation built on `ssh2`, so the same tool surface can in principle run against a remote host (FACT, src: packages/kaos/src/kaos.ts:6-12, packages/kaos/src/ssh.ts:1-20 @486dcd2). Vendor positioning ("single binary", video input, plugin marketplace) is README-level: VENDOR-CLAIM (src: README.md @486dcd2).

## 2. Architecture overview

- **Entry point**: `apps/kimi-code/src/main.ts` parses CLI args via Commander.js (`createProgram` in `apps/kimi-code/src/cli/commands.ts`); UI modes include interactive TUI and `print` (headless) mode selected via `validated.uiMode`; subcommands include `acp`, `doctor`, `export`, `fork`, `login`, `provider`, `session`, `upgrade`, `web`, `migrate` (legacy `~/.kimi` → `~/.kimi-code` migration via `packages/migration-legacy`) (FACT, src: apps/kimi-code/src/main.ts:25-117, apps/kimi-code/src/cli/sub/ @486dcd2).
- **Engine**: `packages/agent-core-v2` hosts the agent loop, tool registry, permission policies, compaction, persistence, hooks, skills, MCP clients, subagents, and session services, organized as DI scopes with `Service`/`Fiber` units and collection contribution points (FACT, src: packages/agent-core-v2/src/ @486dcd2; structure confirmed by repo AGENTS.md which describes the scope tiers — VENDOR-CLAIM for the prose description, FACT for the directory layout).
- **LLM abstraction**: `packages/kosong` contains provider adapters: `kimi.ts`, `openai-legacy.ts`, `openai-responses.ts`, `anthropic.ts`, `google-genai.ts`, plus `capability-registry.ts`, `kimi-files.ts`, `request-auth.ts`, `reasoning-key.ts`, `tool-call-id.ts` (FACT, src: packages/kosong/src/providers/ @486dcd2).
- **Server**: `packages/kap-server` exposes sessions over REST + WebSocket (`/api/v1` + `/api/v1/ws`) and a `/api/v1/debug` reflection RPC surface guarded by loopback bind + bearer auth; `packages/remote-control` implements a tunnel client registering the machine with a relay (FACT, src: packages/kap-server/, packages/remote-control/ @486dcd2; the `/api/v1` path layout per repo AGENTS.md — MIXED).
- **Auxiliary packages**: `packages/transcript` (isomorphic transcript store: L1 agent-granular store, L2 idempotent ops, L3 off/turn/block/delta subscription granularity, L4 framework-free view registry — per repo AGENTS.md, MIXED), `packages/tree-sitter-bash` (pure-TypeScript bash parser, no wasm, deterministic `timeoutMs`/`maxNodes` budget returning a discriminated `ParseResult`), `packages/minidb` (embedded JSON document store with snapshot+WAL, full-text layer), `packages/oauth` (FACT for file presence, src: packages/tree-sitter-bash/, packages/minidb/ @486dcd2).

## 3. Agent loop

- **State-machine loop**: the loop lives in `packages/agent-core-v2/src/agent/loop/loop.ts` with a machine engine at `agent/loop/machine/engine.ts`; the human-facing agent machine is `human/agent/machine.ts` and per-turn streaming is `human/agent/turn.ts`. The loop is actor/state-machine structured (XState-style): it handles input submission, steering, notifications, pause/resume, cancellation, abortion, prompt queueing, background tools, prompt gates, and turn completion/failure/abort as explicit machine transitions (FACT, src: packages/agent-core-v2/src/agent/loop/, packages/agent-core-v2/src/human/agent/machine.ts, turn.ts @486dcd2).
- **Service surface**: `IAgentLoopService` exposes submit, steer, cancel, notifications, snapshots, quiescence detection, engine attach/reset, and ordered loop hooks (FACT, src: packages/agent-core-v2/src/agent/loop/loop.ts @486dcd2).
- **Turn structure**: a turn streams an LLM response (`turn.ts`); if the response contains tool calls the machine transitions to tool execution and then loops back to the model. Turns are multi-step with a configurable `maxStepsPerTurn` (FACT, src: packages/agent-core-v2/src/human/agent/turn.ts @486dcd2).
- **Max-steps guard**: `loop_control.max_steps_per_turn` in config.toml, env `KIMI_LOOP_MAX_STEPS_PER_TURN`; exceeding it produces structured error `loop.max_steps_exceeded` with a user-facing remediation message ("Raise loop_control.max_steps_per_turn in config.toml, or run /update-config then /reload"); a legacy key `max_steps_per_run` is migrated to `max_steps_per_turn` (FACT, src: packages/agent-core-v2/src/agent/loop/configSection.ts:9-53, agent/loop/errors.ts:5-15, agent/loop/loop.ts:55-59 @486dcd2).
- **Retry/recovery**: recovery proposals and retry-budget resolution are integrated into the turn machine and requester layer (FACT — functions present in `human/agent/turn.ts` and the requester code; exact budget defaults not re-verified line-by-line, searched: packages/agent-core-v2/src/human/agent/, src/agent/loop/ @486dcd2).
- **Planning**: the main agent profile can spawn a `plan` subagent and there are dedicated plan/goal/tower tools (tower = a separate protocol with its own paths module, `features/tower/protocol/paths.ts`); plan-mode separation is profile-driven rather than a hard-coded loop phase (FACT, src: packages/agent-core-v2/src/session/agentLifecycle/profile/profiles.ts, packages/agent-core-v2/src/features/tower/ @486dcd2).

## 4. Tool system

- **Inventory** (`packages/agent-core-v2/src/agent/tools/`): Read, Write, Edit, Grep, Glob, Bash, TaskList/TaskOutput/TaskStop, WaitFor, Cron tools, media/image reading, TodoList, Skill, WebSearch, Agent, AgentSwarm, FetchURL, AskUserQuestion, NotifyUser, plan/goal/tower tools, and MCP tools (FACT, src: packages/agent-core-v2/src/agent/tools/ @486dcd2).
- **Edit mechanism**: exact `old_string`/`new_string` string replacement with optional `replace_all`, workspace path resolution, access descriptors, approval rules, and runtime capability leases — the Claude-Code-style search/replace design, no diff format (FACT, src: packages/agent-core-v2/src/agent/tools/edit/editTool.ts @486dcd2).
- **Tool-result size handling**: a dedicated truncation service interface exists with spill-file support and wire-journal path detection (truncated output is spilled to a file the model can re-read in slices) (FACT, src: packages/agent-core-v2/src/agent/tools/ truncation service files @486dcd2; interface names inspected, thresholds not line-verified).
- **MCP client**: stdio, HTTP, remote, and SSE transports plus OAuth callback/provider/token-store infrastructure under `session/mcp` and related modules (FACT, src: packages/agent-core-v2/src/session/mcp/ @486dcd2).
- **Tool gating**: profiles gate which tools an agent sees — the main profile exposes the broad surface plus `coder`/`explore`/`plan` subagents; `explore` is read-only by tool surface and prompt-enforced behavior (FACT, src: packages/agent-core-v2/src/session/agentLifecycle/profile/profiles.ts @486dcd2).
- **Bash safety**: commands are analyzed by the pure-TypeScript `tree-sitter-bash` parser before permission evaluation (see §6) (FACT, src: packages/tree-sitter-bash/, packages/agent-core-v2/src/agent/permissionPolicy/policies/dangerous-command-ask.ts @486dcd2).

## 5. Context management

- **System prompt**: base template `packages/agent-core-v2/src/app/agentProfileCatalog/system.md` — role definition, communication style, tool-use guidance, coding rules, safety guidance, delivery expectations, context-management guidance, environment/project info, and applicable `AGENTS.md` content (FACT, src: packages/agent-core-v2/src/app/agentProfileCatalog/system.md @486dcd2).
- **Instruction files**: `ISessionInstructionsProvider` discovers and injects `AGENTS.md` content + paths into the session; brand dirs are `~/.kimi-code` (global) and `<cwd>/.kimi-code` (project; e.g. `.kimi-code/AGENTS.md`, `.kimi-code/skills`) with legacy `~/.kimi` migrated by `packages/migration-legacy` (FACT, src: packages/agent-core-v2/src/session/sessionInstructions/instructionsProvider.ts, packages/migration-legacy/src/paths.ts:3, and context.ts references to `.kimi-code/AGENTS.md` @486dcd2).
- **Compaction**: `agent/fullCompaction/strategy.ts` + `compaction-instruction.md` — token-estimate-driven; default trigger ratio 0.85, block ratio 0.85, reserved context 50,000 tokens, up to 3 overflow compaction attempts; split boundaries are protected so compaction never splits a user message, an assistant tool-call group, or an incomplete tool exchange; output is a handoff summary for the next model (FACT, src: packages/agent-core-v2/src/agent/fullCompaction/strategy.ts, compaction-instruction.md @486dcd2).
- **Retrieval**: grep/glob/read tools plus `ripgrep` binary resolution/download caching (`rgLocator.ts` resolves an `rg` binary under the share dir with download fallback); no embedding/vector retrieval found — consistent with the survey's no-RAG finding (FACT for grep/glob/rg; NOT FOUND for embeddings, searched: packages/agent-core-v2/src/agent/tools/, packages/kosong/ @486dcd2).

## 6. Safety model

- **Permission modes**: `manual`, `yolo`, `auto` (FACT, src: packages/agent-core-v2/src/agent/permissionPolicy/types.ts @486dcd2).
- **Policy chain**: `permissionPolicyService.ts` evaluates an ordered policy list producing approve/deny/ask results that may carry reasons, approval callbacks, or error resolution. Ordered policies include: explicit user deny/ask/allow rules → auto-mode behavior → session approval history → `dangerous-command-ask` → `sensitive-file-access-ask` → git path checks → YOLO approval → default approval → fallback ask (FACT, src: packages/agent-core-v2/src/agent/permissionPolicy/permissionPolicyService.ts, policies/ @486dcd2).
- **Dangerous-command guard**: `policies/dangerous-command-ask.ts` parses commands with the pure-TS bash parser and forces an ask for `shutdown`, `diskpart`, `format`, `mkfs`, `wipefs`, dangerous `rm -rf`, dangerous `dd`, privilege wrappers, nested shells, and `systemctl` power operations — a real parser, not regex (FACT, src: packages/agent-core-v2/src/agent/permissionPolicy/policies/dangerous-command-ask.ts, packages/tree-sitter-bash/ @486dcd2).
- **Sensitive files**: `sensitive-file-access-ask.ts` forces an approval request for sensitive-path access (FACT, src: packages/agent-core-v2/src/agent/permissionPolicy/policies/sensitive-file-access-ask.ts @486dcd2).
- **OS sandbox**: NOT FOUND — no container/seccomp/Seatbelt isolation in the engine; containment is the permission-policy layer plus the `Kaos` execution abstraction (searched: packages/agent-core-v2/src for `sandbox`, packages/kaos/ @486dcd2).
- **Hooks as safety surface**: `PermissionRequest` hook events let user hooks intercept approvals; hooks can block via exit code 2 (FACT, src: packages/agent-core-v2/src/features/externalHooks/internal/types.ts, runHook.ts @486dcd2).

## 9. Session & state

- **Wire protocol**: `human/persist/v2/wire.ts` — versioned JSONL event-sourced persistence, `V2_WIRE_PROTOCOL_VERSION = '1.5'`. Record kinds cover context appends, loop events, compaction, undo, prompts, cancellation, turn endings, LLM requests, and tool-store updates. The reader validates records, rejects newer unsupported versions, migrates older tool-call formats (`v2/migrate.ts`), and filters by agent ID (FACT, src: packages/agent-core-v2/src/human/persist/v2/wire.ts:4, v2/migrate.ts, v2/fold.ts, v2/convert.ts @486dcd2).
- **On-disk layout**: sessions persist as `state.json` + `wire.jsonl` with per-agent journals under `agents/<id>/wire.jsonl` inside a session directory; brand home is `~/.kimi-code` with per-workspace session buckets (legacy `~/.kimi/sessions/<md5-of-workdir>/` migrated) (FACT, src: packages/agent-core-v2/src/human/persist/, packages/migration-legacy/src/types.ts:37-42 @486dcd2).

## 11. Notable mechanisms

1. **KAOS execution abstraction** (`packages/kaos`): the agent's filesystem/process surface is an interface with local *and* SSH/SFTP-over-`ssh2` implementations — the harness can point identical tools at a remote host without tool-level changes. Most harnesses hardwire `node:fs`/`child_process` (FACT, src: packages/kaos/src/kaos.ts, ssh.ts @486dcd2).
2. **Pure-TypeScript bash parser for safety**: `tree-sitter-bash` runs a deterministic-budget parse (`timeoutMs`, `maxNodes`, discriminated `ParseResult`) and the dangerous-command policy degrades safely when parse aborts — a genuinely structural (not regex) command guard with no wasm/native dep (FACT, src: packages/tree-sitter-bash/, packages/agent-core-v2/src/agent/permissionPolicy/policies/dangerous-command-ask.ts @486dcd2).
3. **Event-sourced versioned session journal**: `wire.jsonl` v1.5 with in-reader migration of older tool-call formats and per-agent journal filtering — sessions are reconstructable event streams, supporting undo/fork/inspect tooling (`apps/vis`, `apps/kimi-inspect`) (FACT, src: packages/agent-core-v2/src/human/persist/v2/ @486dcd2).
4. **Four-tier DI lifecycle**: App/Workspace/Session/Agent scopes with `Service`/`Fiber` units and collection contribution points let the same engine host TUI, SDK, server, and ACP surfaces with per-scope service injection — heavier machinery than most CLI harnesses but it is what makes `klient`'s `global/session/agent` contract facade possible (FACT, src: packages/agent-core-v2/src/app/scopes.ts, packages/klient/ @486dcd2).
5. **Boundary-safe compaction**: compaction splits are blocked at user messages, tool-call groups, and incomplete tool exchanges, with up to 3 overflow retries — the split-boundary rules are the part most harnesses get subtly wrong (FACT, src: packages/agent-core-v2/src/agent/fullCompaction/strategy.ts @486dcd2).
