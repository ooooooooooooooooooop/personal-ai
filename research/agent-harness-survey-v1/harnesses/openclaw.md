## 1. Positioning & design philosophy

OpenClaw bets that the durable asset is the **gateway/session plane, not the agent loop**. It is a personal-AI gateway: a long-running daemon (`src/gateway/`, default port 18789 multiplexing WS+HTTP) that owns channels (~30 messaging plugins), session persistence, tool policy, approvals, and the visible transcript — while the "low level executor for one prepared OpenClaw agent turn" is a **pluggable agent harness** selected per model/provider (src: `docs/plugins/sdk-agent-harness.md`, `src/agents/harness/types.ts`). The built-in `openclaw` runtime is itself just the reserved registry entry (`src/agents/harness/builtin-openclaw.ts`, `registry.ts:46-48`); bundled plugins register `codex` (Codex app-server) and `copilot` (GitHub Copilot CLI via `@github/copilot-sdk` JSON-RPC) harnesses. This is the paper's "ACP third role: harness hosting" made concrete as an in-process registry rather than only a wire protocol (src: arxiv.org/abs/2609.00006). Design rule stated in-repo: "Small core, capable plugins" and "stable conversation context" for prompt-prefix reuse (src: `AGENTS.md`).

## 2. Architecture overview

- **Process model**: one Gateway process per state dir (`~/.openclaw/`, `$OPENCLAW_STATE_DIR`), config `openclaw.json` (src: `src/config/paths.ts:31,220`, `DEFAULT_GATEWAY_PORT = 18789` at `src/config/paths.ts:363`). Entry: `openclaw.mjs` → `src/cli/`; CLI subcommands and channel traffic converge on the same embedded runtime.
- **Monorepo layers**: `packages/` holds runtime-agnostic cores — `agent-core` (the agent loop), `ai`/`llm-core` (model streaming/providers), `plugin-sdk`, `gateway-protocol`, `net-policy`, `retry`, `tool-call-repair`; `src/` holds the gateway host (agents, sessions, channels, plugins, cron, memory, skills); `extensions/` holds ~150 bundled plugins; `apps/` holds macOS/iOS/Android/desktop; `ui/` the web control UI.
- **Agent loop location**: `packages/agent-core/src/agent-loop.ts` (`agentLoop`/`runAgentLoop`/`runLoop`), wrapped by the embedded runner in `src/agents/embedded-agent-runner/` (notably `run-loop.ts::runPreparedEmbeddedLoop`, `run/attempt.ts`, `run-orchestrator.ts`).

## 3. Agent loop

FACTS from `packages/agent-core/src/agent-loop.ts`:

- **Two-level loop**: inner `while (hasMoreToolCalls || pendingMessages.length > 0)` processes streamed tool calls; outer `while (true)` re-enters when `config.getFollowUpMessages()` yields queued follow-ups (lines 310-536).
- **Turn protocol**: events `agent_start` → `turn_start` → `message_start`/`message_end` → `turn_end` → `agent_end` over an `EventStream<AgentEvent, AgentMessage[]>` (lines 80-167). `stopReason` values `toolUse`/`stop`/`error`/`aborted` drive continuation; `message.endTurn === false` (Responses API) forces another request even on text-only replies (lines 416-421; confirmed semantics in `docs/concepts/agent-loop.md`).
- **Steering**: `config.getSteeringMessages` is polled at defined checkpoints — loop start, pre-stream, post-turn — so a user message typed mid-run is injected before the next assistant response (`getSteeringAtCheckpoint`, lines 69-77, 251-255, 513-514).
- **Tool admission**: `config.beforeToolBatch` can return an intervention; `criticalToolLoopSeen` escalation terminates the run with `TOOL_LOOP_RECOVERY_TERMINATED_MESSAGE` without executing the blocked batch (lines 60-61, 584-597, 446-465).
- **Per-turn re-planning**: `config.prepareNextTurn` may swap context/model/thinking level between turns (lines 472-494); `config.shouldStopAfterTurn` is a host stop hook (500-511).
- **Retry/failover above the loop**: `src/agents/embedded-agent-runner/run-loop.ts` + `run/failover-policy.ts`, `run/retry-budget.ts`, `run/idle-timeout-breaker.ts`, `run/incomplete-turn-recovery.ts` (`DEFAULT_EMPTY_RESPONSE_RETRY_LIMIT`, `DEFAULT_REASONING_ONLY_RETRY_LIMIT`), `run/post-compaction-loop-guard.ts`. Model fallback (`action: "fallback_model"`) rotates to configured fallbacks; prompt-timeout fallback only when proven replay-safe (`failover-policy.ts:167-170`).
- **Run guards**: run timeout via `timeoutMs`/abort signal; admitted-run context (`src/agents/admitted-run-context.ts`) is prepared once and reused across retries ("retries and fallbacks reuse that exact context", `src/agents/AGENTS.md`); writer-claim fencing `activeWriterRunId`/`expectedWriterRunId` prevents superseded runs committing transcript bytes (`docs/concepts/agent-loop.md`).

## 4. Tool system

- **Inventory**: the catalog (`src/agents/tool-catalog.ts`) organizes ~40+ built-in tools into sections — `fs` (ls/read/write/edit/apply_patch), `runtime` (exec/process/code_execution/secrets), `web` (web_search/web_fetch/x_search), `memory` (memory_search/memory_get), `sessions` (sessions_*, conversations_*, sessions_spawn, sessions_send, agents_wait, sessions_yield, subagents), `ui` (dashboard/canvas/show_widget), `messaging` (message), `automation` (cron/automations), `nodes`, `agents`, `media` (image/music/video generate, tts). Each tool declares `profiles: ["minimal"|"coding"|"messaging"|"full"]` gating (FACT).
- **Edit mechanism**: `src/agents/sessions/tools/edit.ts` — `edits[]` array of exact targeted search-replace ops (no overlap/nesting), output schema returns `{changed, diff, patch, firstChangedLine}` with unified-diff + patch text (lines 64-88, 481-496). `write.ts` whole-file; `edit-diff.ts`, `file-mutation-queue.ts` (serialized mutations per file), `file-write-verification.ts` (post-write stat). `apply_patch` also exists as a separate catalog tool.
- **Tool-result size**: `src/agents/embedded-agent-runner/tool-result-truncation.ts` (1630 lines) — per-block budgets, `DEFAULT_MAX_LIVE_TOOL_RESULT_CHARS`, spill-to-artifact with `{truncated, spill}` details, dedup'd truncation warnings (`TOOL_RESULT_WARNING_DEDUPE_LIMIT = 1024`).
- **MCP**: client side via `src/agents/agent-bundle-mcp-*` (acquisition, manager lifecycle, tool materialization into the bundle, per-server `McpToolCatalog`, `mcpToolsDeny` overrides); server side via `src/mcp/` (`tools-stdio-server.ts`, `openclaw-tools-serve.ts` — OpenClaw exposes its own tools over MCP). Harnesses may report a **native MCP inventory** (`loadMcpToolCatalog`, `types.ts:536-539`).
- **Tool gating**: profile + allow/deny policy (`src/agents/tool-policy.ts`, `tool-policy-match.ts`, `agent-tools.policy.ts`); group policies (`resolveGroupToolPolicy`); harnesses declare `conversationToolPolicySupport: "exact"` plus `conversationToolPolicySafeDenyTools`/`conversationToolPolicyNativeTools` to map OpenClaw denies onto native tool names — anything unmapped stays **fail-closed** (src: `types.ts:396-404`, codex `harness.ts:118-120`).

## 5. Context management

- **System prompt**: `src/agents/system-prompt.ts` (~1600 lines) composes ordered sections — bootstrap-context notice, safety, tool catalog summary, skills, memory, directory/workspace, docs, project context files, `SYSTEM_PROMPT_CACHE_BOUNDARY` marker, temporal context, delegation/orchestration guidance, output directives, messaging section, voice, watched-sessions. Context-file precedence is explicit: `CONTEXT_FILE_ORDER` = agents.md(10) < soul.md(20) < identity.md(30) < user.md(40) < tools.md(50) < bootstrap.md(60) < memory.md(70) (lines 89-97). Provider plugins may override named sections (`ProviderSystemPromptSectionId`, e.g. `interaction_style`, `tool_call_style`, `execution_bias`).
- **Prompt-cache engineering (FACT)**: `SYSTEM_PROMPT_CACHE_BOUNDARY`, `SYSTEM_PROMPT_RELOCATABLE_BOUNDARY{,_END}` delimit a stable prefix; the `## Runtime` line is kept inside a relocatable region because "automatic literal-prefix caches include Runtime before the tool catalog" (lines ~1554-1568); a stable-prefix cache (`SYSTEM_PROMPT_STABLE_PREFIX_CACHE_LIMIT = 64`) memoizes renders; cron run-scoped session keys are stripped from the runtime line so isolated cron runs share the prefix (lines ~1570-1580).
- **Compaction**: `src/agents/embedded-agent-runner/compact*.ts` family (~20 files) — direct-compaction, checkpoint, successor-session, hooks; per-harness `compact` capability and a Codex-only `nativeCompaction` registry bridge gated by owner id (`registry.ts:23,50-54`). Overflow recovery: `run/overflow-context-recovery.ts`.
- **Retrieval**: memory tools (`memory_search` semantic + `memory_get` file reads) backed by `extensions/memory-core` (FTS rows + vector rows + embedding cache — `cli-index-search.runtime.ts:316`); **code retrieval itself is grep/glob/read tools** — consistent with the paper's "no vector embeddings for code" finding (INFERENCE: embeddings exist for memory, not code navigation). Context-engine subsystem (`src/context-engine/`) lets plugins own assemble/compact/maintain phases; harnesses advertise `contextEngineHostCapabilities` (e.g. codex: bootstrap, assemble-before-prompt, after-turn, maintain, compact, runtime-llm-complete, thread-bootstrap-projection — `extensions/codex/harness.ts:48-56`).

## 6. Safety model

- **Sandbox**: `src/agents/sandbox/` — backend registry (`backend.ts`) with built-ins docker/podman (`docker-backend.ts`, `podman-runtime.ts`) and ssh (`ssh-backend.ts`); fs-bridge for remote FS ops; mount plans, network-mode, noVNC for computer use. `cloudPlacement: { mode: "remote-exec", devicePlacement }` on a harness declares paired-device/cloud execution requirements (`types.ts:383`, codex harness declares `requiredNodeCommands: ["codex.exec-server.stdio.v1"]`).
- **Approvals**: exec approval flow (`src/agents/bash-tools.exec-approval-*`, `agent-tools.before-tool-call.approval.ts`, `agent-run-approval-wait.ts`); channel-native approval prompts (`src/channels/plugins/native-approval-prompt.ts`); ACP permission relay (`src/acp/permission-relay.ts`); exec reviewer outcomes and paired-device command authority are part of the harness contract (`docs/plugins/sdk-agent-harness.md` "user input and execution authority").
- **Untrusted content**: tool results may be wrapped in `<<<EXTERNAL_UNTRUSTED_CONTENT id=…>>>` markers; the loop detector canonicalizes marker ids before hashing outcomes (`tool-loop-detection.ts:74-93`) — evidence of an external-content envelope discipline.
- **Secret handling**: provider-secret egress sentinels (`src/agents/provider-secret-egress.ts` — `unwrapSecretSentinelsForProviderEgress`), `secrets` tool = "write-only credentials" (tool-catalog.ts:120-123), `src/secrets/` store; codex doc: "Secret Store environment values never enter the Codex app-server process" (`docs/plugins/codex-harness.md:112`).
- **Cyber safety**: bundled Codex harness runs a refusal-detection + escalation path (`extensions/codex/harness.ts:297-393`, `cyber-failover.ts`): on `cyberRefused` it may replay the turn on a configured fallback model (Daybreak route per repo AGENTS.md), with per-workspace denial recording + cooloff (`recordCodexCyberTargetUnavailable`).

## 7. Orchestration

- **Subagents**: `sessions_spawn` tool (`src/agents/tools/sessions-spawn-tool.ts`) with `collect` mode (batch fan-out, requires `tools.swarm.enabled` for group params), `sessions_yield` (end turn to receive child results), `agents_wait`, `subagents` (list/cancel background work). Task history can be read natively by a harness (`taskHistory` capability → codex `readCodexNativeSubagentHistory`).
- **Harness hosting (meta-harness)**: `registerAgentHarness()` (`src/agents/harness/registry.ts:39`) plugs external executors into the embedded turn path; selection runs after provider+model resolution (`docs/plugins/sdk-agent-harness/selection-policy`), with `supports(ctx)` returning `{supported, priority, fallbackRuntime: "openclaw"}` for lossless host fallback (`types.ts:57-64`). **CLI backends** are a second, distinct family: e.g. `claude-cli` runs a local CLI process while the model ref stays canonical (`cli-backend-dispatch*.ts`; `docs/concepts/agent-runtimes.md`).
- **Wire protocols**: Gateway WS+HTTP protocol (`packages/gateway-protocol`), `agent`/`agent.wait` RPCs; **ACP** both directions — OpenClaw as ACP agent over stdio (`src/acp/server.ts`, `@agentclientprotocol/sdk`) and as ACP *client* to external agents (`extensions/acpx`, `extensions/a2a`); per paper, "ACP ships in six systems with a new third role: harness hosting" (arxiv.org/abs/2609.00006 — FACT for OpenClaw hosting external runtimes via both registry and ACPX).
- **Multi-surface**: ~30 channel plugins (telegram, discord, slack, signal, whatsapp, matrix, imessage, irc, line, feishu, msteams, mattermost, nostr, nextcloud-talk, synology-chat, twitch, wecom-adjacent zalo/zalouser…), TUI (`src/tui/`), web UI (`ui/`), macOS/iOS/Android apps (`apps/`), cron (`src/cron/`), heartbeat, A2A.

- **Resume/fork**: session catalog (`src/plugins/session-catalog.ts`) with upstream links; harness-level `sessionFork` capability with `upstreamKinds` (codex: `codex-app-server`) and failure codes `steer-message | in-progress-turn | drift-mismatch | upstream-unavailable` (`types.ts:314-350`); native session bindings map OpenClaw sessions ↔ external threads (codex `bindingStore`, copilot `sdk-sessions` keyed store).
- **Writer fencing**: transcript appends require the live `activeWriterRunId` claim; commit transactions verify `expectedWriterRunId` — a superseded run cannot write stale bytes (`docs/concepts/agent-loop.md`).
- **Cross-session memory**: memory plugins + `memory_search`/`memory_get` tools; `extensions/active-memory`; "dreaming" consolidation in memory-core (`extensions/memory-core/src/dreaming-*.ts`).

## 11. Notable mechanisms

1. **Harness-as-registry-entry with fail-closed native bridging** (`src/agents/harness/`): the host prepares everything (session, transcript, tool policy, auth plan) then delegates `runAttempt` — while keeping native tool-policy enforcement honest via `conversationToolPolicySupport: "exact"` + a positive audited deny list (`CODEX_TOOL_POLICY_SAFE_DENY_NAMES` audited against `@openai/codex 0.150.1`, `extensions/codex/harness.ts:27-47`). Unmappable denies isolate the native surface instead of silently passing.
2. **Session-binding lineage**: codex `bindingStore` + `resolveSessionRuntimeOwnership` with `readPreviousSessionId` chain lets native thread ownership survive session-id rotation; copilot's `compatKey`/`compactKey` fingerprinting decides when an SDK session may be reused vs. recreated (`extensions/copilot/harness.ts:72-84`).
3. **Prompt-prefix engineering as architecture**: explicit cache-boundary sentinels, relocatable regions, stable-prefix memoization, and cron-scope stripping — the AGENTS.md makes "rebuilding past context defeats prompt-prefix reuse" a design invariant (src: `src/agents/system-prompt.ts`, `AGENTS.md`).
4. **Tool-loop forensics**: six detector kinds (generic_repeat, argument_churn, unknown_tool_repeat, known_poll_no_progress, global_circuit_breaker, ping_pong) over a 30-call history with warning(→intervention)/critical thresholds at 20/30; outcome digests canonicalize untrusted-content marker ids so injected envelope ids can't fake novelty (`src/agents/tool-loop-detection.ts:28-52,70-93`).
5. **Writer-claim fencing**: `activeWriterRunId` + `expectedWriterRunId` verified inside the synchronous SQLite commit transaction — makes run supersession a storage-level invariant rather than a cooperative convention (`docs/concepts/agent-loop.md`).
