## 1. Positioning & design philosophy

Hermes bets the agent should **accumulate**: the same synchronous agent core runs across CLI, gateway (~20 platforms), TUI, desktop, ACP, and an OpenAI-compatible API, and every turn feeds a learning loop — background review forks that distill turns into skills/memories, an inactivity-driven skill Curator, FTS5 full-text search over its own past sessions, and optional Honcho dialectic user modeling (src: `agent/background_review.py:1-8`, `agent/curator.py`, `plugins/memory/honcho/`). Two stated invariants shape the harness (repo `AGENTS.md`, FACT): per-conversation prompt caching is "sacred" (system prompt is byte-stable for a session; only compression may mutate context; mid-conversation info rides user messages or tool results), and "the core is a narrow waist" — new capability lands as CLI+skill, service-gated tool, plugin, or MCP server before it may become a core tool ("Footprint Ladder").

## 2. Architecture overview

- **Facade + siblings**: `run_agent.py::AIAgent` is assembled from ~15 mixins (`ClientLifecycleMixin`, `StreamDeliveryMixin`, `SessionPersistenceMixin`, `CompressionFacadeMixin`, `TurnFacadeMixin`, …, `run_agent.py:107-121`); `AIAgent.__init__` takes ~60 params; `chat()` is the simple API, `run_conversation()` returns `{final_response, messages}` (src: `agent/AGENTS.md`).
- **Turn loop**: `agent/conversation_loop.py::run_conversation` + one file per phase under `agent/turn_*.py` (preflight → iteration prep → request assembly → api call → error → response intake/check → tool round → overflow/truncation/compaction → recovery → stop gates → finalizer).
- **Surfaces**: `cli.py`/`hermes_cli/` (REPL + ~50 subcommands), `gateway/` (messaging runner), `tui_gateway/` (Python JSON-RPC backend serving `ui-tui/` Ink-React TUI and `apps/desktop/` Electron), `acp_adapter/` (ACP stdio server for Zed/VS Code/JetBrains), `gateway/platforms/api_server.py` (OpenAI-compatible HTTP, port 8642, `API_SERVER_KEY`).
- **State**: `hermes_state*.py` — `SessionDB` facade over 21 sibling modules; SQLite WAL at `~/.hermes/state.db` (profile-aware `HERMES_HOME`), sessions+messages+FTS5. `~/.hermes/config.yaml` settings; `~/.hermes/.env` secrets only.

## 3. Agent loop

FACTS (`agent/conversation_loop.py`, `agent/AGENTS.md`):

- **Entirely synchronous** single-threaded loop (line 1514): `while (api_call_count < max_iterations and iteration_budget.remaining > 0) or _budget_grace_call:` — a one-turn grace call lets the model close out after budget exhaustion.
- **Iteration guards**: `max_iterations` from `agent.max_turns` config (default 500; `cli-config.yaml.example:1068`); `IterationBudget` (`agent/iteration_budget.py`) is a thread-safe consume/refund counter shared with subagents (each `delegate_task` child gets `delegation.max_iterations`, default ~250); `execute_code` programmatic tool calls refund iterations so RPC-driven loops don't eat the budget (lines 20-25, `refund()`).
- **Phase pipeline per iteration**: `begin_iteration` → `prepare_iteration` → `assemble_api_request` → `run_preflight_gate` (can return/break/continue) → `announce_api_call` → `_run_api_retry_loop` (inner retry/fallback machinery) → `apply_retry_restarts` → `normalize_model_response` → `run_tool_round` (tool calls) or `finish_text_response` — each phase a `turn_*.py` sibling returning `{action: break|continue|return}` (lines 1514-1549).
- **Retry/fallback**: `turn_retry_state.py::TurnRetryState`, `turn_api_error.py::handle_api_error`, credential rotation via `CredentialPool` leases (`agent/credential_pool.py:893+`, `acquire_lease`/`release_lease`), model fallback chains (`hermes_cli/fallback_config.py::get_fallback_chain`), `_arm_fallback_restart` rebuilds the request on the fallback provider (conversation_loop.py:1082).
- **Run bounds**: `--run-budget` wall-clock budget injects a one-time wrap-up notice at 80% (`RUN_BUDGET_WRAPUP_NOTICE`, lines 71-75, 119-130); gateway inactivity timeout (`agent inactivity timeout` config); interrupt flags checked each iteration; `repetition_guard.py`/`tool_guardrails.py` provide loop detection (see §4).
- **Codex transport escape**: `api_mode == "codex_app_server"` hands the whole turn to a Codex app-server subprocess (`agent/transports/codex_app_server_session.py`, `conversation_loop.py:1505-1511`) — Hermes can delegate a turn to an external native runtime, a lighter-weight cousin of OpenClaw's harness registry.

## 4. Tool system

- **Registry**: `tools/registry.py` — each `tools/*.py` calls `registry.register()` at import declaring schema/handler/toolset/`check_fn`; `model_tools.py::discover_builtin_tools()` imports them; `handle_function_call` → `registry.dispatch` (line 823+). `check_fn` results TTL-cached 30s process-wide; **service-gated tools** appear only when their prerequisite is configured (FACT).
- **Core toolset** (`toolsets.py::_HERMES_CORE_TOOLS`, ~60 names): `web_search`, `web_extract`, `terminal`, `process_manage`, `read_file`, `write_file`, `patch`, `search_files`, `vision_analyze`, `image_generate`, `skills_list`, `skill_view`, `skill_manage`, full `browser_*` suite + `browser_vault_*` (credential fill), `text_to_speech`, `todo_list`, `memory`, `session_search`, `clarify`, `execute_code`, `delegate_task`, `cronjob_manage`, `ha_*` (Home Assistant), `kanban_*` (12 tools), `computer_use`, `manage_connections`. Named toolsets (`coding`, platform bundles `hermes-*`, `delegation`, `session_search`, …) fold in per session surface; `_HERMES_WEBHOOK_SAFE_TOOLS` strips file/system exec for untrusted webhook payloads.
- **Edit mechanism**: `tools/patch_parser.py` — **V4A patch format** (`*** Begin Patch` / `*** Update File:` + `@@ hint @@` context + ` `-`+` lines / `*** Add File:` / `*** Delete File:` / `*** Move File: a -> b`), markers must anchor at column 0 so content lines can't truncate the patch (lines 38-44); plus `write_file` (whole file) and `patch` tool. `file_operations*` handle the FS layer; `file_tools_read_tracking` supports read-before-write guards.
- **Result size handling**: `_MAX_TOOL_ERROR_CHARS = 2048` bound for error bodies (`tools/registry.py:25-33`); tool-result classification (`agent/tool_result_classification.py`) distinguishes mutation outcomes for loop detection; mid-turn pressure estimator feeds pre-API compression (`conversation_loop.py:78-104`).
- **MCP**: full client in `tools/mcp_tool*.py` — stdio/Streamable-HTTP/SSE, one daemon anyio loop, `MCPServerTask` per server, discovered tools registered into the same registry (`mcp_*` names); **OSV malware preflight** on stdio spawns, wall-clock-bounded 12s fail-open (`_OSV_MALWARE_CHECK_TIMEOUT_S`, lines 30-38); elicitation/sampling handlers; `optional-mcps/` ships a server catalog; `agent/transports/hermes_tools_mcp_server.py` exposes Hermes tools as an MCP server.
- **Loop guardrails**: `agent/tool_guardrails.py` — side-effect-free controller tracking per-turn tool-call observations, `IDEMPOTENT_TOOL_NAMES` vs `MUTATING_TOOL_NAMES` sets, decisions render as warning guidance, synthetic tool results, or controlled halt.
- **`execute_code`**: runs model-written Python in a sandbox and lets it call tools over a host-side RPC bridge — UDS/TCP socket locally, filesystem polling on remote backends, `secrets.compare_digest` token auth + `allowed_tools` frozenset (`tools/code_execution_rpc.py:33-49`); iterations refunded per `IterationBudget`.

## 5. Context management

- **System prompt**: `agent/system_prompt.py` — three tiers joined by `\n\n`: `stable` (identity, guidance, env/backend hints, coding brief, platform hints), `context` (workspace snapshot, caller system_message, context files), `volatile` (skills index, memory, USER.md, external memory provider block, timestamp). Built once per session; restored sessions re-parse the cached prompt rather than re-running plugin section code (`_frozen_plugin_prompt_sections`, lines 112-120). Plugin sections carry framed markers (`## Plugin Context: <id>` + char-count comment, line 33).
- **Context files**: `agent/prompt_builder.py` — CWD-only at startup; filenames `AGENTS.override.md > AGENTS.md/agents.md > CLAUDE.md > .cursorrules`, HERMES.md; `_scan_context_content` **blocks** injection-flagged content (line 81); YAML frontmatter stripped; caps `CONTEXT_FILE_MAX_CHARS=20_000` / 6% of context window / 500k ceiling (lines 1026-1041); install-tree AGENTS.md never loaded as project context.
- **Progressive discovery**: `agent/subdirectory_hints.py` — as tool calls touch subdirectories, their AGENTS.md/CLAUDE.md are appended **to the tool result** (never the system prompt — cache-preserving), 32KiB cap with head+tail truncation + warning, ancestor walk ≤5, dependency/cache dirs pruned via `SEARCH_PRUNE_DIR_NAMES`.
- **Compression**: two layers (FACT, `agent/AGENTS.md`): gateway session hygiene at 85% and agent `ContextCompressor` at 50% (`compression.threshold: 0.50`, `hermes_cli/config_defaults.py:536`, per-model `model_thresholds`, raise-only floor for small contexts). Algorithm prunes old tool results first (no LLM call), picks boundaries, then summarizes with the auxiliary compression model; manual `/compress` on every surface via `conversation_compression_manual.py::compress_now`; native Responses/Codex compaction supported for eligible providers; `ContextEngine` ABC (`agent/context_engine.py`) lets `plugins/context_engine/<name>/` replace the whole strategy.
- **Retrieval**: `session_search` tool over FTS5 (below); memory via `memory` tool + providers; **no vector embeddings for code** — consistent with the paper's corpus-wide finding (arxiv.org/abs/2609.00006; memory providers may embed, but code nav is `search_files`/grep).

## 6. Safety model

- **Hardline floor** (FACT, `tools/approval_detection.py`): `HARDLINE_PATTERNS` = never-bypassable blocks, even in YOLO mode — recursive delete of root/system/home dirs, fork bomb, redirect-to-raw-block-device, mkfs/dd variants (lines 78-129). Quote-masked variants (`_mask_quoted_strings`) match positionless rules against quote-blanked text so `echo "cat f > /dev/sda"` prose doesn't trigger while real commands still do (lines 126-175). Comment cites real-world tuning: 118/125 hardline blocks in a week were false-positive-adjacent, driving the masking design.
- **Approval tiers**: `tools/approval.py` — dangerous-command detection → per-session approval queue (`submit_pending`, `resolve_gateway_approval`), `session`/`always` choices persisted per pattern key; approval transports pluggable (`register_approval_transport`, `hermes_cli/plugins.py:434`); context detectors skip prompts for cron/unattended/single-query surfaces (`tools/approval_context.py:126-148`); `tirith` content-level checks (homograph URLs etc.) run after pattern detection, `security.tirith_fail_open` governs unimportable-tirith behavior (approval.py:588-608). Container-class backends may `skip_container_guards` (disposable sandboxes skip dangerous-command prompts — `agent/terminal_env_provider.py:33-34,52-54`).
- **Secrets**: `agent/redact.py` (1222 lines) — regex secret redaction for logs/tool output, force-redact paths, vault-value registry (`«redacted-vault-secret»`), on by default (`HERMES_REDACT_SECRETS`/`security.redact_secrets`); per-backend `strip_env_keys` removes vendor credentials (MODAL_*, DAYTONA_API_KEY…) from every spawned subprocess (`agent/terminal_env_provider.py:37-38`, `terminal_env_registry.py:69-83`); secret sources are plugins (`register_secret_source`, run after `.env` load).
- **Sandboxing**: container/remote backends are the sandbox story — docker/singularity/modal/daytona/vercel_sandbox/ssh; `docker_egress.py` network policy; `terminal_scope.py`, `local_env_policy.py` for the local backend; sudo-password plumbing is callback-gated (`terminal_tool_sudo.py`).

- **SQLite-blackboard swarm** (FACT, `hermes_cli/kanban_swarm.py`): "Kanban Swarm v1" writes a task graph into the existing kanban kernel — planning root + parallel `SwarmWorkerSpec` cards + verifier (todo until workers done) + synthesizer; shared blackboard = structured JSON comments prefixed `[swarm:blackboard]` on the root task in `task_comments`/`task_events` rows (`kanban_db.py` schema: tasks/task_links/task_comments/task_events/task_runs/task_attachments/kanban_notify_subs) — no second scheduler; dashboard, notifier, and dispatcher all reuse the same rows. `kanban_*` model tools let agents read/write the board.

## 11. Notable mechanisms

1. **The learning loop as background review** (`agent/background_review.py:1-8`): after each turn a daemon-thread **forked AIAgent** replays the conversation snapshot asking "should any skill/memory be saved or updated?" — writes go straight to memory/skill stores under a dispatch-side tool whitelist; the fork inherits the parent's live runtime so it hits the same prefix cache; `_skill_nudge_interval`/`_memory_nudge_interval` (default 10 turns) pace the nudges; bounded deadline so self-improvement never stalls the live turn. `/learn` (`agent/learn_prompt.py`) turns "what we just did" into a skill with explicit authoring standards (≤60-char description rule because the system-prompt skill index truncates at 60) and an anti-injection hygiene block for untrusted sources.
2. **Skill Curator** (`agent/curator.py`): inactivity-triggered (no daemon) lifecycle manager — auto-transitions skills through states from activity timestamps (stale 14d, archive 30d), opt-in LLM consolidation fork via the auxiliary client, `.curator_state` JSON; invariants: only curator-managed skills touched, never delete (archive is recoverable via `hermes curator restore`), pinned skills bypass transitions. `tools/skill_usage.py` keeps `.usage.json` provenance (`created_by`, use counts).
3. **Environment-provider ABC as policy carrier** (`agent/terminal_env_provider.py`): `TerminalEnvironmentProvider` turns historical frozensets of built-in names into declarative attributes — `is_remote` (suppress host hints), `is_container` (path resolution + container config), `skip_container_guards` (disposable ⇒ no dangerous-command prompts), `cache_path_base`, `strip_env_keys` (vendor creds removed from every spawned subprocess), `session_isolated_when_nonpersistent`. Built-in names are registry-reserved so a plugin can never shadow `local/docker/singularity/modal/managed_modal/daytona/vercel_sandbox/ssh` (`terminal_env_registry.py:26-34`). Seven user-facing backends in `tools/environments/` (README says "seven"; `managed_modal` is an internal alias).
4. **SQLite-blackboard swarm** (`hermes_cli/kanban_swarm.py`): parallel multi-agent work coordinated through structured JSON comments (`[swarm:blackboard]` prefix) on kanban rows inside the same DB — workers/verifier/synthesizer are just task cards; no new service or scheduler.
5. **Hardline + quote-masked command gating** (`tools/approval_detection.py`): a never-bypassable pattern floor (even YOLO can't `rm -rf /`), with quote-masking and command-position anchoring to keep prose mentions from false-positiving — plus the tirith content-level layer and pluggable approval transports that let a gateway channel render the same prompt natively.
6. **execute_code RPC bridge** (`tools/code_execution_rpc.py`): programmatic tool-calling inside the sandbox over UDS/TCP or remote FS polling, token-authed with an `allowed_tools` allowlist, and iteration refunds so scripted pipelines cost zero context turns.
