## 1. Positioning & design philosophy

Crush's bet is **"your tools, your code, your workflows, wired into your LLM of choice"** — a provider-agnostic terminal agent where the model layer is a swappable catalog entry, not the product. The LLM abstraction (`charm.land/fantasy` v0.43.1) and the provider/model catalog (`charm.land/catwalk` v0.52.28, fetched over HTTP with ETag caching + an embedded fallback snapshot) are separate Charm libraries shared with other Charm tools (FACT, src: go.mod, internal/config/catwalk.go:37-96 @8b2b285). The second bet is **LSP as first-class agent context**: language servers auto-start per filetype and expose diagnostics/references/symbols/rename/call-hierarchy as agent tools, so the agent navigates code the way an IDE does rather than via text search alone (FACT, src: internal/lsp/manager.go, internal/agent/coordinator.go:808-821 @8b2b285). The third bet is structural minimalism: a Go-native shell (mvdan/sh interpreter), SQLite+sqlc persistence, and a Bubble Tea v2 TUI — no Node, no Electron, CGO disabled (FACT, src: internal/shell/dispatch.go:18-20, internal/db/, repo AGENTS.md @8b2b285).

## 2. Architecture overview

- **Entry**: `main.go` → `internal/cmd` (cobra). Modes: `crush` = interactive Bubble Tea TUI (`--yolo`, `--session <id>`, `--continue`, `--host` to attach to a running server, `--channels` hidden flag for MCP-as-channel), `crush run` = single non-interactive prompt (`--quiet`, `--model`, `--small-model`, `--reasoning-effort`, session continue flags), `crush server` = HTTP daemon (FACT, src: internal/cmd/root.go:55-115, run.go:33-160, server.go:20-60 @8b2b285).
- **Client/server split**: the TUI can run in-process or attach over `--host`/`CRUSH_CLIENT_SERVER` to `crush server`; the server exposes a versioned REST+SSE API (`/v1/...`) over Unix socket (`$XDG_RUNTIME_DIR/crush-<uid>.sock`, 104-byte path cap), Windows named pipe, or TCP (FACT, src: internal/cmd/root.go:58,235-236, internal/server/server.go:30-99, endpoints.go @8b2b285).
- **Core layering**: `internal/app/app.go` wires DB (SQLite via sqlc), `config.ConfigStore` (atomic-swap service), `agent.Coordinator`, `lsp.Manager`, MCP init (`mcp.ArmInit`/`mcp.Initialize` async), pub/sub brokers, `herdr` multiplexer client, clipboard (FACT, src: internal/app/app.go:93-185 @8b2b285).
- **Agent layer**: `internal/agent/coordinator.go` (`Coordinator` → named agents `coder`/`task`) → `internal/agent/agent.go` (`sessionAgent` → `fantasy.NewAgent`/`agent.Stream`) — the step loop itself lives in the external `charm.land/fantasy` library; crush supplies `PrepareStep`/`OnStepFinish`/`StopWhen` hooks and persistence (FACT, src: internal/agent/coordinator.go:115-139, agent.go:685-1065 @8b2b285).
- **Key packages**: `internal/shell` (mvdan/sh interpreter + in-process coreutils builtins + background jobs), `internal/lsp` (auto-start manager over powernap server registry), `internal/permission`, `internal/hooks`, `internal/skills`, `internal/session`+`internal/message`+`internal/db`, `internal/server`+`internal/backend` (daemon), `internal/herdr` (terminal-multiplexer status reporting), `internal/ui` (Bubble Tea v2 TUI), `internal/config`+`internal/shellconfig` (FACT, src: internal/ layout @8b2b285).

## 3. Agent loop

- **Turn structure**: `Coordinator.Run` → `sessionAgent.Run` → `fantasy.NewAgent(model, WithSystemPrompt, WithTools, WithUserAgent)` → `agent.Stream(AgentStreamCall{...})` with rich per-step callbacks (FACT, src: internal/agent/agent.go:685-796 @8b2b285).
- **Per-step hook**: `PrepareStep` runs before each model call — refreshes the tool list (MCP tools can appear mid-turn via `SetTools`), **drains the session's queued follow-up prompts and folds them into the running turn** (prompts carrying a `RunID` are left queued to run as separate turns), applies provider media workarounds, sets Anthropic cache-control on the last system message + last 2 messages, prepends an optional system-prompt prefix, and creates the assistant `message` row that streaming callbacks append into (FACT, src: internal/agent/agent.go:808-879 @8b2b285).
- **Streaming callbacks**: `OnReasoningStart/Delta/End` (persists Anthropic signatures, Google thought signatures, OpenAI Responses reasoning metadata), `OnTextDelta`, `OnToolInputStart`/`OnToolCall`/`OnToolResult` (tool calls + results persisted as message rows mid-stream), `OnRetry` (resets streamed content on retry), `OnAuthRefresh` (401 → token refresh → transparent retry), `ModelProvider` (model can be swapped mid-run via `SetModels`) (FACT, src: internal/agent/agent.go:880-982 @8b2b285).
- **Stop conditions**: `StopWhen` has exactly two checks — (1) context-window auto-summarize: when `prompt+completion tokens` approach the model's `ContextWindow` (buffer 20k tokens if window >200k, else 20% of window; skipped when window unknown or `disable_auto_summarize`), and (2) repeated-tool-call loop detection over a sliding window (`hasRepeatedToolCalls` with `loopDetectionWindowSize`/`loopDetectionMaxRepeats`) (FACT, src: internal/agent/agent.go:1039-1064, loop_detection.go @8b2b285). No fixed max-turns in crush's own code — the step ceiling, if any, lives inside `charm.land/fantasy` (INFERENCE — external lib not vendored).
- **Queueing/cancellation**: prompts submitted while a session is busy are queued per session; an elaborate accept-sequence scheme (`BeginAccepted`/`AcceptedRun`/`cancelMark`) serializes dispatch under a per-session mutex so a `Cancel` covers everything accepted up to that point but never poisons later prompts; canceled RunID-bearing prompts still get a terminal `RunComplete` so headless clients never hang (FACT, src: internal/agent/agent.go:160-500 @8b2b285).
- **Summarize**: `Summarize` runs a separate fantasy agent with `templates/summary.md` (handoff-briefing prompt: Current State / Files & Changes / Technical Context / Strategy / Exact Next Steps, "assume all previous messages will be lost"); the summary is stored as a message flagged `is_summary` and `sessions.summary_message_id` truncates history on resume (FACT, src: internal/agent/agent.go:1336-1450, templates/summary.md, internal/db/sql/sessions.sql:10 @8b2b285).
- **Auth recovery**: 401 → `OnAuthRefresh` (OAuth refresh, AWS SSO transparent refresh) → transparent retry; the coordinator coalesces the failed attempt + retry into one terminal `RunComplete` so `crush run` doesn't exit on the stale error (FACT, src: internal/agent/coordinator.go:301-365, aws_sso_refresh.go @8b2b285).

## 4. Tool system

- **Inventory** (built in `coordinator.go:783-829`): `bash`, `view`, `edit`, `multiedit`, `write`, `ls`, `glob`, `grep`, `sourcegraph`, `fetch`, `agentic_fetch`, `download`, `web_fetch`, `web_search`, `agent` (task subagent), `todos`, `question` (interactive only), `diagnostics`, `references`, `lsp_restart`, `lsp_symbols`, `lsp_definition`, `lsp_call_hierarchy`, `lsp_rename`, `lsp_replace_symbol`, `list_mcp_resources`, `read_mcp_resource`, `crush_info`, `crush_logs`, `job_output`, `job_kill` + MCP tools (FACT, src: internal/agent/coordinator.go:783-829, internal/agent/tools/ @8b2b285).
- **Tool docs as files**: every tool ships a `.md`/`.md.tpl` description file embedded via `go:embed` and rendered as a Go template (e.g. bash description injects the banned-command list, `rg`/`gh` availability, attribution rules) — "tools are self-documenting" per repo AGENTS.md (FACT, src: internal/agent/tools/bash.go:58-73, tools.go:81-105 @8b2b285).
- **Edit mechanism**: exact-match find/replace (`edit` single, `multiedit` multi) + `write` whole-file; edits integrate LSP (diagnostics feedback) and `filetracker`/`history`; `lsp_replace_symbol`/`lsp_rename` offer **semantic edits** that bypass text matching entirely — the system prompt actively steers the model to prefer LSP edits for whole-symbol changes (FACT, src: internal/agent/tools/edit.go, lsp_replace_symbol.go, templates/coder.md.tpl `<editing_files>` block @8b2b285).
- **Shell**: `bash` runs through `mvdan.cc/sh/v3` — a Go-native POSIX shell interpreter with a custom exec-handler chain (shebang dispatch → registered in-process builtins incl. coreutils/jq → os/exec); output capped at `MaxOutputLength = 30000`; commands auto-background after `auto_background_after` (default 60s) or `run_in_background`, polled via `job_output`/`job_kill` against a background shell manager (FACT, src: internal/agent/tools/bash.go:50-56,248-299, internal/shell/dispatch.go, background.go @8b2b285).
- **MCP tools**: `tools/mcp/` client; `GetMCPTools` exposes server tools filtered per-agent by `AllowedMCP` map (server→tool allowlist) (FACT, src: internal/agent/coordinator.go:838-860, internal/agent/tools/mcp/ @8b2b285).
- **Tool gating**: per-agent `AllowedTools` (nil = all) + `Options.DisabledTools` subtraction + `resolveReadOnlyTools` for the read-only profile; `question` withheld from subagents and non-interactive runs; LSP tools only when LSPs configured or `auto_lsp` on (FACT, src: internal/config/config.go:661-682,958-1003, coordinator.go:803-821 @8b2b285).

## 6. Safety model

- **Permission service** (`internal/permission/permission.go`): pub/sub request/response — a tool calls `Request(ctx, {session, tool_call_id, tool, action, params, path})`; the service checks `skip` (yolo) → `allowedTools` allowlist (`tool` or `tool:action` entries) → hook pre-approval stamp → per-session auto-approve → session-persistent grant cache keyed `(SessionID, ToolName, Action, Path)` → else publishes a `PermissionRequest` and blocks on a channel until a UI/server client calls `Grant`/`GrantPersistent`/`Deny`; requests are serialized (`requestMu`, one `activeRequest`) (FACT, src: internal/permission/permission.go:181-310 @8b2b285).
- **Deny semantics**: denial returns a `StopTurn` tool response ("User denied permission") so the agent loop ends the turn rather than retrying (FACT, src: internal/agent/tools/tools.go:64-70 @8b2b285).
- **YOLO**: `--yolo` flag → `Overrides().SkipPermissionRequests` → `SetSkipRequests`; `AutoApproveSession` per-session equivalent; server endpoint `/permissions/skip` toggles it remotely (FACT, src: internal/cmd/root.go:60,288, internal/permission/permission.go:280-295, internal/server/endpoints.go:250-273 @8b2b285).
- **Shell hard-block layer**: independent of permissions, the bash interpreter enforces `blockFuncs()` at the exec-handler level — banned binaries (curl, wget, ssh, nc, browsers, sudo/su/doas, package managers, `systemctl`, `mount`, `iptables`, `crontab`…) plus argument-level blocks (`apt install`, `npm i -g`, `pip install --user`, `go test -exec`, `cargo install`…) that can't be approved away; safe read-only command prefixes bypass the permission prompt entirely (FACT, src: internal/agent/tools/bash.go:75-246 @8b2b285).
- **Hooks before permissions**: `hookedTool` decorator runs `PreToolUse` hooks **before** the permission check; a hook `allow` stamps the context (`WithHookApproval(toolCallID)`) so the permission service grants without prompting (FACT, src: internal/agent/hooked_tool.go, internal/permission/permission.go:192-202 @8b2b285).
- **OS sandbox**: NOT FOUND — no container/seccomp/Seatbelt; containment = exec-handler blocklists + permission prompts (searched: internal/shell/, internal/permission/, internal/agent/tools/ @8b2b285). The shell package has `isolation_unix_test.go` (test-only name); no production isolation primitive found.
- **Network policy**: soft — network tools are prompt-banned + exec-blocked; no egress proxy found (FACT for blocklist, src: internal/agent/tools/bash.go:75-146; NOT FOUND for proxy, searched: internal/ @8b2b285).

## 7. Orchestration

- **Subagents**: `agent` tool (`NewParallelAgentTool`) spawns the `task` agent — a separate `sessionAgent` built with the task prompt (`templates/task.md.tpl`), its own tool filter, and a **child session** (`CreateTaskSession`, `parent_session_id` set); sub-agent tools run without hook interception to avoid firing user hooks N times per delegated turn (FACT, src: internal/agent/agent_tool.go:26-68, coordinator.go:865-871, internal/db/sql/sessions.sql:5 @8b2b285).
- **Multi-client server**: `crush server` exposes ~70 REST endpoints under `/v1` — workspaces CRUD, per-client `current-session`, sessions/messages/history, SSE event stream (`/workspaces/{id}/events?client_id=`), agent send (202, detached — survives client disconnect), cancel, queued-prompt list/clear, summarize, shell exec, permissions skip/grant, questions answer/cancel, LSP start/stop/diagnostics, config set/model/compact/provider-key/import-copilot/refresh-oauth, MCP refresh/auth(OAuth URL polling)/docker enable, project init, skills list/read, filetracker — plus `shutdown_if_idle` control and OpenAPI docs at `/v1/docs` (FACT, src: internal/server/endpoints.go:11-598 @8b2b285).
- **Wire protocol**: HTTP/1.1 + cleartext HTTP/2 (`h2c`) on unix socket/npipe/TCP; SSE for events; `proto` package defines the DTOs (FACT, src: internal/server/server.go:150-165, internal/proto/ @8b2b285).
- **Multiplexer integration**: `internal/herdr` reports agent state (idle/working/blocked) and session identity to the `herdr` terminal multiplexer over its Unix socket API (FACT, src: internal/herdr/client.go:1-50 @8b2b285).
- **Headless**: `crush run` (quiet/verbose, model override, session continue); runs wait for MCP init bounded by `InitWaitBudget` rather than per-server timeouts so a wedged server can't stall a headless turn (FACT, src: internal/cmd/run.go:33-160, coordinator.go:255-275 @8b2b285).
- **Channels**: hidden `--channels` flag enables "MCP servers as channels" (e.g. `server:webhook`) — an inbound-trigger surface (FACT for flag+plumbing, src: internal/cmd/root.go:61-62; semantics beyond the flag NOT FOUND, searched: internal/cmd/, internal/agent/tools/mcp/ @8b2b285).

## 10. Model layer

- **Abstraction**: `charm.land/fantasy` — `fantasy.LanguageModel` + `fantasy.ProviderOptions` with provider-specific option parsers; two configured slots, `large` (main agent) and `small` (titles, summaries, task agent default `isSubAgent` path) (FACT, src: internal/agent/agent.go:76-158, coordinator.go:876-904 @8b2b285).
- **Catwalk catalog**: provider/model metadata (context window, max tokens, `CanReason`/`ReasoningLevels`/`DefaultReasoningEffort`, image support, default small model) comes from **Catwalk** — fetched via HTTP with ETag, cached on disk, embedded snapshot as offline fallback; `disable_provider_auto_update`/`disable_default_providers` controls; `crush update-providers`-style refresh (FACT, src: internal/config/catwalk.go:30-96, config.go:390-391 @8b2b285).
- **Providers**: fantasy adapters wired in `buildProvider`/`getProviderOptions` — anthropic, azure, bedrock, google, openai (chat + Responses API detection via `IsResponsesModel`), openaicompat, openrouter, vercel, plus first-party `hyper` (Charm's own inference, `internal/agent/hyper` with embedded `provider.json`) and Prism-savings metadata extraction (FACT, src: internal/agent/coordinator.go:46-56,389-566, agent/hyper/ @8b2b285).
- **Auth**: API keys via config/`config provider-key` endpoint; OAuth for Copilot (`internal/oauth/copilot`, `import-copilot` endpoint) and OpenAI (`internal/oauth/openai`); AWS SSO transparent refresh; per-request `OnAuthRefresh` retry on 401 (FACT, src: internal/oauth/, internal/server/endpoints.go:440-455, coordinator.go:295-365 @8b2b285).
- **Per-provider quirks**: extensive — Copilot model→Responses-API map, OpenCode Zen/Go models routed to Anthropic-Messages or OpenAI-Responses by `modelID` prefix, Alibaba provider `extra_body` thinking/reasoning split, io.net `reasoning.effort` shape, MiniMax `thinking` param, gemini-2 `thinking_budget` vs `thinking_level`, OpenRouter/Vercel `reasoning:{effort}` (FACT, src: internal/agent/coordinator.go:70-113,442-566 @8b2b285).
- **BYOK**: first-class — any OpenAI/Anthropic-compatible endpoint via `providers` config or catwalk-merged custom providers (FACT, src: internal/config/config.go:391,762 @8b2b285).
- **Mid-session switch**: `SetModels`/`ModelProvider` callback lets the model change between steps of the same run ("switch LLMs mid-session while preserving context" is implemented, not just marketing) (FACT, src: internal/agent/agent.go:2117-2134,943-949 @8b2b285).

## 11. Notable mechanisms

1. **Catwalk: provider catalog as a service** — model capabilities (context window, reasoning levels, defaults) live in a remotely-updated, ETag-cached, embedded-fallback catalog shared across Charm tools, so new models/quirks ship without a crush release; provider-quirk tables in `coordinator.go` show how far the team goes to normalize vendor differences (FACT, src: internal/config/catwalk.go, internal/agent/coordinator.go:389-566 @8b2b285).
2. **mvdan/sh embedded shell + exec-handler blocklists** — the agent's `bash` is a Go interpreter with in-process coreutils/jq builtins and a dispatch chain where `CommandsBlocker`/`ArgumentsBlocker` hard-ban binaries (curl/sudo/apt…) and argument shapes (`npm i -g`, `go test -exec`) *below* the permission layer — un-approvable, no syscall sandbox needed for the common cases (FACT, src: internal/agent/tools/bash.go:165-246, internal/shell/dispatch.go @8b2b285).
3. **LSP-as-tools**: eight LSP tools (symbols/definition/references/call-hierarchy/rename/replace_symbol/diagnostics/restart) with auto-start by filetype and root markers; the prompt explicitly prefers `lsp_replace_symbol` over text edit for whole-symbol work — semantic editing is a first-class path, not a side feature (FACT, src: coordinator.go:808-821, templates/coder.md.tpl `<editing_files>` @8b2b285).
4. **Multi-client daemon protocol**: the `/v1` surface treats clients as first-class (`client_id` claims, per-client current-session, detached 202 agent runs, SSE fan-out, `shutdown_if_idle` arbitration) — the same agent serves TUI, `crush run`, and third-party clients concurrently against shared workspaces (FACT, src: internal/server/endpoints.go, server.go @8b2b285).
5. **Accept-sequence cancel correctness**: the `BeginAccepted`/`cancelMark`/per-session-dispatch-mutex machinery guarantees a `Cancel` covers exactly the prompts accepted before it — queued RunID prompts each get their own terminal `RunComplete`, queued non-RunID prompts *fold* into the active turn at the next `PrepareStep` (a steering mechanism). Concurrency correctness this explicit is rare in agent harnesses (FACT, src: internal/agent/agent.go:160-500,808-836 @8b2b285).
