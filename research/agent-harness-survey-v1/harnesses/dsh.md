## 1. Positioning & design philosophy

DSH's bet (as evidenced by this repo) is **composition over code**: the harness is a Cordis service tree in which the agent loop, tools, persistence, sandbox/approval, model route, and UI are all mountable/replaceable units, composed per profile from `package.json` bundles plus a patch file — the profile `cordis.yml` is deliberately an empty entry list (src: `dsh-config/profiles/web/cordis.yml`, `dsh-config/profiles/web/package.json`). Personal AI treats DSH as its only "deeply managed" harness: the repo's AIC control plane owns the whole runtime composition (pinned Node runtime + pinned base npm distribution + pinned UI build + managed plugin rows + generated settings and instruction blocks) with `aic diff dsh` as drift authority, while Claude Code/Codex/Gemini remain `NATIVE_INDEPENDENT` and agent-switchboard stays an `OPTIONAL_TOOL` (src: `registry/harnesses/dsh.yaml`, `docs/durable-execution-gap-report.md` §0, `registry/harnesses/switchboard.yaml`, `docs/architecture.md`). The user-level plugin surface is the deliberate extension seam — `ctx.on` waterfalls, `ctx.tools.guard()`, `systemPrompt.section`, `ctx.tools.register`, `ctx.web.registerSearchProvider`, and service injection let governance be layered onto a closed runtime without forking upstream (src: `docs/cordis-plugin-guide.md`, `dsh/*/README.md`).

## 2. Architecture overview

- **Process model**: one Node host process per profile. The launcher resolves the managed Node (`runtime/node-v22.19.0-win-x64`), enforces the version range `>=22.19.0 <23 || >=24`, verifies the pinned package identity `@deepseek-ai/dsh@0.1.1-rc.2` from the distribution's own `package.json`, then runs `node base-dsh-0.1.1-rc.2/node_modules/@deepseek-ai/dsh/lib/bin.js web --no-open` (src: `dsh/runtime/launch-web.ps1`). `base-distribution.json` additionally pins `baseEntrySha256`/`uiBundleSha256` and forbids `npx`-resolved launches (FACT) (src: `dsh/runtime/base-distribution.json`).
- **Composition**: the profile `package.json` declares `dsh.profile.bundles` = `@deepseek-ai/dsh-base`, `@deepseek-ai/dsh-web-app`, `dsh-remote-web-gateway`, `dshmarket`; each bundle contributes its own `cordis.patch.yml`; the profile patch applies after every bundle layer; `--patch` overlays are possible. Presets (`.agent-presets/cc/agent.cordis.yml`) mount the agent plane once per process under `isolate` realms so per-session services do not collide, while the host plane owns registries, the sandbox/approval stack, persistence, and the model route (src: `dsh-config/profiles/web/package.json`, `dsh-config/profiles/web/cordis.patch.yml`, `dsh-config/.agent-presets/cc/agent.cordis.yml`).
- **Module inventory**: `runtime_provided_services` in the adapter contract enumerates ~110 Cordis services — the de-facto upstream module map: `agent`, `agent-loop`, `goal`, `goal-round-driver`, `command-goal`, `plan-mode`, `token-meter`, `compaction`, `command-compact`, `subagent`, `subagent-spawn-in-process`, `subagent-fork-in-process`, `tool-subagent*`, `workflow-worker-thread`, `tool-workflow`, `tool-ralph`, `tool-jobs`, `tool-todo`, `tool-str-replace-editor`, `tool-fs`, `tool-fs-search`, `tool-web`, `web-search-deepseek`, `tool-skill`, `skill`, `skill-filesystem`, `session-persistence-jsonl`, `session-query-sqlite`, `session-projection`, `session-telemetry-otel`, `sandbox`, `sandbox-policy`, `pwsh-sandbox`, `bash-sandbox`, `fs-sandbox`, `fs-observation-policy`, `approval`, `permission`, `shell-env`, `llm`, `llm-pi-ai`, `llm-retry`, `llm-deepseek`, `system-prompt`, `spill-local`, `spill-policy`, `session-checkpoint-policy`, `tool-result-pruner`, `repeat-tool-reminder`, `storage`, `storage-json`, `storage-domain`, `workspace`, `agent-presets`, plus web/client services (`webStartup`, `webserver`, `webRuntime`, `connection`, `slots`, `sessions`, `workspaces`, …) (FACT for service names; INTERNAL for implementations) (src: `registry/harnesses/dsh.yaml`).
- **Agent loop location**: upstream packages `@deepseek-ai/dsh-agent` / `@deepseek-ai/dsh-agent-loop` — INTERNAL/NOT PUBLISHED as upstream source. The repo does ship a patched fork of the agent-loop package (`dsh/context-pressure-guard/lib/index.js`) whose exported `AgentLoop` dispatches the `agent/request` waterfall, calls `llm.prepareCall`, handles `agent/request-error`, and exports `CONTEXT_PREFLIGHT_BLOCKED` — direct source evidence of the loop's interception seams (src: `dsh/context-pressure-guard/lib/index.js`).

## 3. Agent loop

Documented behavior (FACT from published artifacts; upstream internals INTERNAL/NOT PUBLISHED):

- **Turn/step structure**: a session is an event stream persisted as multi-frame zstd JSONL; event types observed in plugin source: `turn/start`, `turn/end`, `step/start`, `tool/call`, `tool/result`, `assistant/message` (including `reasoning` content blocks), `todo/write`, `user/message`, `session/event` (src: `dsh-config/profiles/web/plugins/session-supervisor.mjs`, `dsh/world-model/world-model.mjs`, `scripts/find_session.py`).
- **Goal continuation**: the `goal` service plus `goal-round-driver` drive multi-round autonomous continuation; `command-goal` provides the `/goal` command; the model-facing tools are `create_goal`/`update_goal`/`get_goal` via `tool-goal`; `max_goal_rounds` bounds rounds (10 in the production pilot config); goal status is coarse `ACTIVE`/`BLOCKED`/`COMPLETE` and session-scoped (src: `registry/harnesses/dsh.yaml`, `dsh-config/.agent-presets/cc/agent.cordis.yml`, `research/cognitive-leverage-pilot-v0/configs/current_personal_ai.json`, `docs/durable-execution-gap-report.md` §1-2, `dsh-config/AGENTS.md` §5).
- **Orchestration state** is implemented by DSH (`dsh-agent`, Cordis Fiber state): `RUNNING`, `WAITING`, `ROUND_LIMIT`, `ENDED`, `BLOCKED` — explicitly decoupled in the audit from business `JOB_STATE` so a round-limit stop is not misread as job failure (src: `docs/durable-execution-gap-report.md` §1, mirrored in `scripts/jobs/models.py` `OrchestrationState`).
- **Cordis interception seams** (FACT, from plugin sources): `agent/pre-step` waterfall returning decisions `{kind:'enter'|'block', messages, additionalContexts, feedback}`; `agent/request` waterfall (provider/model switch interception); `agent/request-error`; `tools/post-execute` (can inject `additionalContexts` into the next model input); `tools/result`; `system-prompt/assemble` waterfall; `session/event`; `ctx.tools.guard()` pre-dispatch guard; `ctx.tools.register`; `ctx.effect` cleanup; `inject` dependency array (src: `dsh-config/profiles/web/plugins/session-supervisor.mjs`, `dsh/model-persona/model-persona.js`, `dsh/subagent-prep-exec-gate/README.md`, `dsh/workflow-model-preflight-gate/README.md`).
- **Stop conditions**: native goal round limit; native `repeat-tool-reminder` per-session duplicate-call reminder (a patch note documents guarding its `agent/pre-step` hook against undefined `messages`); plan-mode exit via `exit_plan_mode`; plugin hard stops (governor budget/loop-breaker fail-closed at `tools.guard` + durable checkpoint); context exhaustion → `READ_ONLY_*` sidecar + handoff (src: `dsh/repeat-tool-reminder-patch/README.md`, `dsh-config/.agent-presets/cc/agent.cordis.yml`, `dsh/autonomous-execution-governor/README.md`, `dsh/context-lifecycle/README.md`). Exact upstream stop-condition implementation: INTERNAL/NOT PUBLISHED.
- **Retry/recovery**: per-provider `retryPolicy` (`mode`, `maxRetries`, `retryableCodes` = `EMPTY_RESPONSE`/`RATE_LIMIT`/`SERVER`/`TIMEOUT`/`TRANSPORT`, exponential `backoff` with `initialDelayMs`/`maxDelayMs`/`jitterRatio`) — native since rc.7, per the patch comment that upstream's "Claude Code baseline retry + `CONTEXT_WINDOW_EXCEEDED` classification" made earlier user plugins redundant (src: `registry/providers.yaml`, `dsh-config/profiles/web/cordis.patch.yml` header, `dsh/token-saver/README.md`). Unsafe assembled requests fail locally before provider dispatch (`CONTEXT_PREFLIGHT_BLOCKED`) (src: `dsh/context-pressure-guard/README.md`).
- **Compaction in-loop**: `compaction-basic` (configured `summarizationProvider`/`summarizationModel`, `maxTokens`, `maxOverflowRetries`, `maxConsecutiveFailures`) runs inside the session; the repo fork adds convergence guards; `/compact` via `command-compact` (src: `dsh-config/.agent-presets/cc/agent.cordis.yml`, `dsh/compaction-convergence/README.md`).
- **INFERENCE**: the loop is a Cordis-fiber step machine where a "turn" may contain multiple steps; `goal-round-driver` re-enters while the goal is active and under `max_goal_rounds`; plugins see `agent/pre-step` before each model call. Exact scheduling/termination internals: INTERNAL/NOT PUBLISHED.

## 5. Context management

- **System prompt composition**: the `system-prompt` service exposes `systemPrompt.section({name, order, text|fn})`; the `system-prompt/assemble` waterfall lets plugins rewrite sections with the *current request's* provider/model (`variables.provider/model`, refreshed mid-conversation by `dsh-agent.installModelSelection`). Observed ordering: persona (order 0, `dsh-persona` template with `{{model}}`/`{{cwd}}`), world-model briefing (order 10), model-persona steering (order 50 — "after persona, before tool guidance 100-199"), plan-mode section when active (src: `dsh/model-persona/model-persona.js`, `dsh/model-persona/README.md`, `dsh/world-model/world-model.mjs`, `dsh-config/.agent-presets/cc/agent.cordis.yml`). The full upstream section list and assemble order: INTERNAL/NOT PUBLISHED.
- **Instruction files**: the `agent-instructions` service (`maxBytes 65536`) loads AGENTS.md layering — user-global `~/.dsh/AGENTS.md` (published skeleton: five preference modules — token economy, event-driven supervision, cheap-labor delegation, domestic-source preference, self-rescue-before-blocked — plus two checksum-managed generated blocks, `CONTINUOUS_CAPABILITY_ADOPTION` and `AUTONOMOUS_EXECUTION_GOVERNANCE`, under `<!-- aic:*:begin sha256=… -->` markers) and project-level `AGENTS.md` (src: `dsh-config/AGENTS.md`, `registry/harnesses/dsh.yaml` `render_targets`, `dsh-config/.agent-presets/cc/agent.cordis.yml`).
- **Skills**: `skill-filesystem` discovers `~/.dsh/skills/` (populated by `sync_skills.py` from `skills/`); `tool-skill` provides catalog/loading; `SKILL.md` instructions inject on activation (workflow-level, not permanent system prompt) (src: `docs/sync-ongoing.md`, `skills/*/SKILL.md` `triggers` frontmatter, `docs/phase5-multiharness-report.md` §4).
- **History/session context**: the session event stream (`agent.session.events`) is readable by plugins; the Personal AI Context Package is injected at the session's first frame for DSH ("DSH=会话首帧注入"), built by `scripts/memory/context_builder.py` with a `project → personal → global` scope chain, derived-score ranking, char budget, and per-item provenance (src: `docs/phase5-multiharness-report.md` §9, `scripts/memory/context_builder.py`).
- **Compaction**: `compaction-basic` + `command-compact`; repo fork `dsh-compaction-convergence` adds checkpoint-aware region selection, unchanged-region pressure convergence (a stable surface fingerprint stops re-invoking the summarizer), a cross-step non-shrinking breaker (opens after three failures), and stale-tool-result preference (src: `dsh/compaction-convergence/README.md`). - **Context admission**: `agent-loop-pressure-guard` estimates the fully assembled request (`inputMultiplier 1.08`), uses min(configured, provider-attested) capacity, reserves `safetyMargin 16384`, caps output at `operationalMaxOutput 65536`, degrades to `conservativeFallbackLimit 262144` when capacity truth is unknown; unsafe requests fail locally `CONTEXT_PREFLIGHT_BLOCKED` before `prepareCall`, and the prepared call is dispatched exactly once (src: `dsh/context-pressure-guard/README.md`, `registry/harnesses/dsh.yaml` `managed_rows`, `dsh/model-switch-controller/README.md`).
- **Exhaustion/handoff**: `context-lifecycle` writes sidecar state `READ_ONLY_CONTEXT_EXHAUSTED`/`READ_ONLY_ARCHIVED` (`archiveThresholdTokens 800000`, `sidecarDir ./.dsh-context-lifecycle`); `agent/request` rejects archived sessions locally; `export()` produces `DSH_HANDOFF_V1` — goal, active change, incomplete tasks, decisions, files, commit, artifact hashes, tests, blockers, observability snapshot — tool history and reasoning explicitly NOT copied; `requestExternalRestart()` persists the handoff and returns `RESTART_REQUIRED`, never self-kills (src: `dsh/context-lifecycle/README.md`, `registry/harnesses/dsh.yaml` `archive_anchor`).
- **Delegation context**: `dsh-subagent-context-summary` gives fork children a compaction summary + the last 1 turn when the parent exceeds 30k chars (README claims ~50-70% child-side input savings in typical scenarios); `subagent-splice-summarizer` lossy-compresses long `subagent-report` messages to governance fields (`status/changed/validation/deviations/blocker/artifact/…`) on `agent/pre-step`, keeping non-text blocks verbatim (src: `dsh/token-saver/README.md`, `dsh/subagent-splice-summarizer/README.md`, `dsh-config/profiles/web/cordis.patch.yml`).
- **Retrieval**: code navigation is `glob`/`grep`/`read`; Dynamic Memory retrieval is a derived score (retention_prior 0.4 / recency 0.2 / relevance 0.4, never persisted) — **no embeddings in evidence anywhere**, consistent with the survey's "nobody uses embeddings for code" finding (FACT for the Personal AI memory path; INTERNAL for any upstream retrieval internals) (src: `registry/retrieval-policy.yaml`, `scripts/memory/provider.py`).
- **Prompt-cache awareness**: the plan-mode section explicitly keeps the tool catalog unchanged across modes "for request-cache stability"; model-persona emits identical text per model so the KV prefix stays stable (FACT, stated in artifacts) (src: `dsh-config/.agent-presets/cc/agent.cordis.yml`, `dsh/model-persona/README.md`).

## 6. Safety model

- **Fail-closed dispatch**: `ctx.tools.guard()` — returning a reason string blocks the tool call before dispatch; every decision appends an audit JSONL line (`workflow-preflight-audit.jsonl`, `governor-audit.jsonl`) (src: `dsh/workflow-model-preflight-gate/README.md`, `dsh/autonomous-execution-governor/README.md`).
- **Bounded autonomy**: `autonomous-execution-governor` enforces `agent_turns` (tool-action proxy, conservative), `provider_calls`, and `runtime_min` at the guard layer; a loop breaker tracks repeated identical tool+args hashes and no-progress windows (soft → hard `circuit_broken`); checkpoint cadence writes `checkpoint.py save` every N turns; a hard stop writes a durable checkpoint (`stop_reason=BUDGET_LIMIT`/`LOOP_BREAKER`) + audit; internal plugin errors fail-open but are audited; default is observation mode (no `taskId` = zero side effects); execution-profile admission runs before the first expensive call (`UNKNOWN ≠ UNBOUNDED` → safe default `AUTONOMOUS_STANDARD`; agents cannot pick a wider profile) (src: `dsh/autonomous-execution-governor/README.md`, `docs/autonomous-execution-governance-report.md`, `docs/automatic-execution-profile-admission-report.md`, `registry/execution-profiles.yaml`). Token/cost hard gates live outside the guard (per-call token accounting is unavailable at that layer) — documented honest limitation enforced instead by `checkpoint.py` usage snapshots + `usage_ledger.py` runaway detection (src: `dsh/autonomous-execution-governor/README.md` REMAINING_LIMITATIONS).
- **Governance firewall**: `auto_allowed`/`auto_forbidden` in `governance-policy.yaml` (`raise_execution_budget`, `bypass_budget_limit`, `disable_loop_breaker`, `unbounded_resume`, `admit_model`, `change_default_model`, … all forbidden); all canonical mutation is proposal-only (DETECTED→PROPOSED→human applies) — "治理只发现和提案，不会偷偷改 canonical 把状态变绿" (src: `registry/governance-policy.yaml`, `docs/phase7-governance-report.md` §23, `docs/personal-ai-operations.md` §4).
- **Consequential mutation**: `world-model`'s `tools.guard` requires a bound prediction for consequential mutations in CORE/FULL modes; evaluated/superseded predictions do not authorize; irreversible operations require `irreversible:true` (src: `dsh/world-model/README.md`).
- **Single writer**: `scripts/jobs/lease.py` atomic SQLite lease (TTL, `LeaseDeniedError` on active competing writer); `scripts/workspace/provisioner.py` worktree write scopes; the workspace-registry incident produced Phase-1 single-instance launch guards + a read-only integrity validator; the root fix (cross-process lock/CAS/write-time invariant) is `PENDING_UPSTREAM_BASE_REBUILD` (src: `scripts/jobs/lease.py`, `docs/dsh-workspace-registry-integrity-incident-handoff.md`, `docs/dsh-workspace-registry-root-fix-spec.md`).
- **Secrets**: `.credentials.yaml` is excluded from sync/publish; `settings.yaml` carries only `apiKeyEnv` names; the durability ledger rejects secret-regex writes; `publish_check.py` scans for device paths/secrets (src: `skills/dsh-config-sync/SKILL.md`, `docs/phase6-durability-report.md` §14, `docs/publishing.md`).
- **Sandbox**: `sandbox`, `sandbox-policy`, `pwsh-sandbox`, `bash-sandbox`, `fs-sandbox`, `fs-observation-policy` services exist on the host plane (FACT they exist; enforcement model INTERNAL/NOT PUBLISHED). `authorized_root` is enforced at the durable-job layer on the repo side (src: `registry/harnesses/dsh.yaml`, `scripts/jobs/registry.py`).
- **Network**: local web server (`dsh-host-webserver`, `dsh-host-apiproxy`), remote-gateway bundle `dsh-remote-web-gateway`, `web-search-deepseek` provider (needs a DeepSeek key; global rules forbid calling it unconfigured and delegate search via switchboard); the user `web-search-adapter` registers a key-free DuckDuckGo-Lite provider via `ctx.web.registerSearchProvider` (src: `dsh-config/profiles/web/package.json`, `dsh-config/AGENTS.md` §3, `dsh/web-search-adapter/README.md`, `skills/agent-switchboard-ops/SKILL.md`).

## 7. Orchestration

## 11. Notable mechanisms

1. **`ctx.tools.guard()` as a portable law-enforcement seam.** Three independent governance planes — model admission (`workflow-model-preflight-gate`), execution budgets (`autonomous-execution-governor`), and world-model consequential-mutation gating — all plug the same monotonic pre-dispatch guard on a closed runtime, fail closed, and write audit JSONL. Because `tools/pre-execute` does not reach profile plugins, the guard is *the* interception point (src: `dsh/workflow-model-preflight-gate/README.md`, `dsh/autonomous-execution-governor/README.md`, `dsh/world-model/README.md`).
2. **Context defense in depth.** Admission-time preflight (measured bound + 16,384 reserve + 65,536 output cap → `CONTEXT_PREFLIGHT_BLOCKED` before provider dispatch) + artifact-backed tool-result pruning with `restore()` + convergence-guarded compaction + read-only exhaustion with structured `DSH_HANDOFF_V1` + four-mode model switching — five published overlays, each owning exactly one failure mode (src: `dsh/context-pressure-guard/README.md`, `dsh/compaction-convergence/README.md`, `dsh/context-lifecycle/README.md`, `dsh/model-switch-controller/README.md`).
3. **Checksum-managed instruction blocks.** Canonical policy renders into the user's own `AGENTS.md` as `<!-- aic:*:begin sha256=… -->` blocks; `aic diff` detects any hand edit as drift and `apply` restores — turning "prompted policy" into generated, auditable state (src: `dsh-config/AGENTS.md`, `registry/harnesses/dsh.yaml` `render_targets`, `docs/autonomous-execution-governance-report.md` AIC_INTEGRATION).
4. **Orchestration/job decoupling + zero-LLM recovery.** The durable plane keeps `ORCHESTRATION_STATE` (DSH's own lifecycle) strictly separate from `JOB_STATE`/`WORKER_STATE`/`VALIDATION_STATE` in a local SQLite registry with atomic leases, machine checkpoints, a sole final adjudicator on an L0–L4 evidence ladder, and a Task-Scheduler-driven `durable_execution_recovery_tick` that never spawns a duplicate worker while one is alive — fixing the documented "round-limit kills the agent but the worker still runs" conflation without a daemon (src: `scripts/jobs/`, `docs/durable-execution-gap-report.md`).
5. **Composition-as-config.** The profile `cordis.yml` is intentionally empty; the whole process tree is bundle patches + profile patch + preset files, with `isolate` realms controlling service lifetime (per-preset vs host singleton) and `!!js` expressions doing platform gating — and AIC registers even the `!!js` opaque paths so silent growth is drift-detectable (src: `dsh-config/profiles/web/cordis.yml`, `dsh-config/.agent-presets/cc/agent.cordis.yml`, `registry/harnesses/dsh.yaml` `opaque_paths`, `registry/TECH_DEBT.md`).

- **No upstream source**: the DSH implementation itself (`@deepseek-ai/*` packages) is a pinned npm distribution, not vendored source — the agent loop's exact file layout, stop-condition code, tool registration code, complete system-prompt section order, sandbox/approval policy model, wire protocol, and provider internals are INTERNAL/NOT PUBLISHED. - **Historical vs current state**: `docs/durable-execution-gap-report.md` (2026-09-03 audit) reports `DURABLE_JOB_REGISTRY=MISSING`, `RECOVERY_SUPERVISOR=MISSING`, `SINGLE_WRITER=POLICY_ONLY`; the repo now contains `scripts/jobs/` implementing those components — the study presents this as evolution (gap → implementation), not simultaneous fact.
- **Version drift in artifacts**: the managed-rows contract configures `compaction-basic-convergence` with `gemini-3.8-flash-high` while the published live `cordis.patch.yml` skeleton records `gemini-3.7-flash-high`; the AIC contract is the newer authority (src: `registry/harnesses/dsh.yaml` vs `dsh-config/profiles/web/cordis.patch.yml`).

- **Optional dependencies**: agent-switchboard is `OPTIONAL_TOOL` (never a mandatory supervisor); `dsh-schedule` is referenced by rules but has no published plugin source; the `headless` profile is referenced but only the `web` profile skeleton is published.
- **No commit pin**: this study cites repo-relative paths at access-date state; no repository commit hash was recorded as the citation anchor.
- **Session/runtime identifiers** present in source artifacts (e.g. the `archive_anchor` session id) were deliberately not reproduced here per the repo's publication boundary.
