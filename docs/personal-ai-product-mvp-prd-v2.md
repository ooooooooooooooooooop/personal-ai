## 2. 产品定位与成功方向

**Personal AI 是一个能跨时间和会话持续合作的个人 AI：理解主人的目标与现实状态，选择并推进下一步，从真实结果中发现错误、修订认知，并保持主人的最终决定权。**

前端应让用户感受到清晰、精致、稳定和可控制。功能应减少用户反复恢复上下文、催促继续、查证虚假完成和纠正重复错误的负担。

本版围绕一条完整链路：

**提出目标 → 恢复相关状态 → 选择并执行行动 → 得到真实结果 → 主人检查或纠正 → 形成受治理认知 → 在后续任务中使用。**

界面不能只完成聊天展示，也不能要求主人为了使用 AI 而填写内部认知流程表。

### 2.1 本版要消除的问题

| 问题 | 用户受到的影响 | 本版对应要求 |
| --- | --- | --- |
| 界面层级混乱、字号和状态不一致 | 难阅读、难找入口、缺乏产品感 | 统一页面结构、设计变量、组件与交互状态 |
| 请求失败后显示模拟成功 | 用户误以为任务完成 | 生产路径不注入假历史、假结果、假工具回执 |
| 按钮只改前端状态 | 点击停止、批准、切换后，实际状态未必改变 | 所有动作有真实命令、回执和状态核对 |
| 新旧页面测试对象不一致 | 测试通过不能证明实际使用版本可用 | 构建、测试、桌面入口绑定同一交付版本 |
| 会话和认知无法可靠续接 | 用户反复解释，旧错误继续影响后续行动 | 持久状态、版本来源、跨会话恢复和认知纠正 |
| 用功能存在代替效果证据 | 无法判断产品是否变好 | 功能、治理、实际加载和效力分别评价 |

## 3. 用户任务与使用场景

| 任务 | 用户要做什么 | MVP 应提供的结果 |
| --- | --- | --- |
| T1 恢复使用 | 新设备或故障后恢复工作 | 复用已有 bootstrap、同步和备份入口，得到可核实的恢复报告 |
| T2 日常工作 | 讨论、研究、整理文档、执行工程或其他任务 | 用自然语言交代目标，持续推进，交付真实结果 |
| T3 掌握状态 | 判断应用和正在执行的工作是否正常 | 看到实际连接、运行、同步和认知加载状态，能停止与处理异常 |
| T4 学习与纠正 | 看见新认知，阻止错误生效，纠正旧认知 | 查看证据、采纳或否决提案，通过治理路径修订 |
| T5 理解依据 | 了解 AI 当前信什么、为什么这样行动 | 日常语言解释当前认知、约束、证据和不确定性，可进入纠正路径 |

承接原任务标尺：具备环境与账号条件时沿用 30 分钟恢复目标；应用打开后 3 秒内出现健康状态区域，尚未取得的信息显示未知。其他响应时延先测量基线，不编造性能成绩。

### 4.2 P1 与非目标

P1：命令面板、历史置顶和标签、更多预览格式、更细的工作区组织。仅在 P0 路径稳定后投入。

本版不新增：多用户组织体系、插件市场、移动端、云端托管工作区、复杂认知图谱、全知世界模型、自动取得更高治理权限。

任务、调度和委派沿用已有能力，验收声明支持的真实组合，不重新建设一套调度平台。

| 页面 | 默认显示 | 主要操作 | 失败与空态 |
| --- | --- | --- | --- |
| P01 工作台 | 当前位置、当前任务、消息、实际状态、输入区 | 新建、发送、追加指示、停止、审批、查看结果 | 保留输入，显示失败原因和恢复动作；无历史时使用真实空态 |
| P02 任务与执行 | 真实任务及状态，不用虚构卡片补满列表 | 继续、查看检查点、取消已有可取消任务 | 无任务就明确显示；无权限或无能力说明原因 |
| P03 文件与产物 | 文件名、类型、任务来源、时间与验证状态 | 打开、复制、查看 Diff、支持的恢复 | 空态、读取失败、权限拒绝、版本冲突分别呈现 |
| P04 理解与学习 | 与当前项目相关的有效认知和待裁决提案 | 查看依据、采纳、否决、提出纠正 | 未挂载、未加载、陈旧、损坏、无记录分别呈现 |

| P06 设置 | 服务、认证状态、模型、目录、外观等真实配置 | 测试连接、保存、切目录、切主题 | 保存失败不显示已保存，未取得配置不填假值 |
| P07 引擎面板 | 已发现引擎、能力、适格性、当前实际引擎 | 资格预检、切换、查看阶段与错误 | 不适格明确拒绝，未验证明确标记 |

P07 可放在设置页和顶栏快捷抽屉，二者使用同一数据源和操作逻辑。健康区域可放在侧栏底部并展开详情，不另造大型仪表盘。

## 6. 五条核心用户流程

### 6.1 首次开始真实工作

打开桌面应用 → 查看健康状态 → 选择工作目录 → 配置或复用模型服务 → 测试连接 → 选择真实可用模型 → 输入目标 → 接收真实响应。

没有配置时提供简短引导。示例任务只能填入输入框，等待用户发送。界面不能自动注入“已经完成诊断”的对话。

### 6.2 完成任务并交付结果

提出目标 → 保存目标与约束 → 获取必要上下文 → 执行并显示真实活动 → 必要时请求审批 → 核实结果 → 展示完成情况与产物 → 保存未完成事项。

测试通过、生成文件、任务完成是不同结论。目标未满足时保留未完成状态和下一步责任。

### 6.3 停止、拒绝与恢复

运行中点击停止 → 发送真实中止请求 → 显示停止中 → 核对执行状态 → 确认停止或显示无法确认 → 说明已经发生的改动。

审批前可批准或拒绝。修改待审批参数后必须按新载荷重新验证，不能沿用旧批准。断线恢复先核对动作是否已执行，再决定是否重试。

### 6.4 隔天继续

打开应用 → 找到原会话或未完成任务 → 恢复消息、目标、约束、检查点与待观察预期 → 核对可能过期的事实 → 继续推进。

不同会话的草稿、消息、审批和运行事件不能互相污染；项目切换不能自动携带不适用的领域事实或一次性授权。

### 6.5 从结果形成认知并在后续使用

真实工作结果或反馈 → 按既有规则识别候选认知 → 展示依据、适用范围与推翻条件 → 主人裁决 → 受治理写入 → 编译 → 核对后续任务加载与使用。

没有充分证据时允许没有提案。候选生成、裁决、写入、编译和后续使用分别显示，不能用其中一步替代整个学习闭环。

## 7. 功能需求

### F01 · 就绪、配置、恢复与退出（P0）

- 列出当前模型服务、认证状态与可选择模型；不在界面硬编码“已连接”。
- 连接测试实际访问所选服务或已有可信测试路径；失败保留错误与恢复方式。
- 配置保存以服务端回执和后续读取为依据。密钥使用受保护存储，不回显、不进入日志或模型上下文。
- 工作目录切换说明对当前会话与运行的影响，保护未发送输入。
- 复用既有 bootstrap、同步、备份和恢复入口，显示通过、失败、跳过、未知及所需处理。
- 提供组件退出或卸载范围预览；认知、会话、凭据与组件分开，实际删除仍遵守授权。

**完成条件：** 从桌面入口配置成功并完成真实消息往返；错误配置能恢复；受控恢复演练有记录；退出预览准确区分私有资产。

### F02 · 目标理解与持续推进（P0）

- 以自然语言输入任务，保存最终目标、必要约束、交付物与完成条件。
- 输入、附件、选定会话和工作目录按现有协议发送；字段名与服务端契约一致。
- 请求接收、执行开始、工具完成与任务完成分别显示；不依赖不存在的字段判定送达或完成。
- 消费真实回复、工具、审批、运行与错误事件。流式内容归属正确的会话和执行轮次。
- 允许按引擎已声明能力追加指示；没有该能力时明确说明。
- 多个未完成事项时，下一步与目标、依赖、信息价值、风险及成本有可说明关系。
- 失败用于更新后续判断；不反复无效重试，不制造与目标无关的活动。
- 结果绑定实际证据，不能以固定文案、模型自述或演示工具输出代替。

**完成条件：** 一个真实多步任务可以持续推进；真实工具事件和结果可回查；失败、拒绝、超时和证据不足均不出现假完成。

### F03 · 会话、草稿与持久续接（P0）

- 会话新建、列表、选择、读取历史和恢复全部使用真实会话生命周期。
- 选择历史后加载对应内容，不能只改变标题或会话 ID。
- 草稿按实例、工作区与会话区分保存；切换页面和重启后能恢复；发送失败不丢原文。
- 目标、进度、约束、未完成事项、预期和证据指针持久化；摘要保留边界与回查入口。
- 事件和异步响应绑定会话及执行身份；旧会话的迟到消息不能写入新会话。
- 为有副作用的提交使用已有幂等与核对机制；回执未知时先核对，不能直接重复执行。
- 一次性授权不在重启或新会话中自动变成永久授权。

**完成条件：** 两个会话可来回切换而消息和草稿不串线；重启及跨日续接保留必要状态；回执丢失时不重复副作用。

### F04 · 运行状态、停止、审批与健康（P0）

- 显示准备就绪、发送中、运行中、等回复、等批准、受阻、停止中、已停止、失败、完成或无法确认。
- 连接状态与任务状态独立：断线不等于任务停止，也不等于任务完成。
- 显示可得的实际活动和持续时间；不伪造百分比、剩余时间、思考时长或执行阶段。
- 停止入口唯一、醒目、可用键盘触达；没有停止回执前保留停止中或无法确认。
- 停止后不再启动后续动作，不让已取消的本地回调生成成功结果。
- 审批卡展示对象、实际载荷、影响范围与不可恢复部分；响应必须到达真实执行侧。
- 已失效、已响应或属于其他会话的审批不能再次执行；重复点击应安全去重。
- 健康区只显示已取得状态及观测时间，错误、未知、陈旧与未加载分别说明。

**完成条件：** 停止、批准、拒绝、审批过期、断线和恢复均有双向证据；不存在只改变按钮样式却不控制执行的路径。

### F05 · 真实结果、产物、变更与后悔权（P0）

- 结果摘要先说明做成了什么、依据是什么、仍缺什么；原始日志和 Diff 按需展开。
- 产物列表与文件变更回执分开，关联真实任务或会话来源。
- 产物可打开或导出；格式不支持预览时保留下载或外部打开方式。
- 真实 Diff 来自文件操作回执或已有差异接口；不能把导出文件列表解释成版本历史。
- 恢复操作绑定实际回执及版本；存在后续编辑或并发冲突时拒绝覆盖。
- 只对确实可恢复的改动展示撤销；不可逆动作事前说明。
- 空列表、加载失败和权限拒绝不填充演示文件；复制失败不能显示复制成功。

**完成条件：** 一个真实产物可打开；一个受管理变更可查看真实 Diff 并恢复；后续编辑受到保护；空态与异常真实。

### F06 · 认知提案、裁决与纠正（P0）

- 复用真实结果与反馈，保留来源、时间、适用范围和证据类型。
- 一次性要求、权限、偏好、事实纠正与方法命题分别处理；当前任务纠正不必等待长期提案。
- 提案包含要改变什么、支持依据、不确定性、行动意义与推翻条件。
- 用户可采纳、否决或提出修正；没有完整期限、退出与恢复语义时不提供试用按钮。
- 提案决策沿用现有受治理路径；界面及对话代理不能直接写 canonical。
- 写入、编译、加载与后续使用分阶段显示，失败停在哪一步可见。
- 纠正、替代与回退保留原因和版本；否决及已替代内容不能继续作为有效认知。
- 立即提炼只触发既有流程，不保证会产出提案，不制造“已学会”文案。

**完成条件：** 真实任务证据形成候选并走通采纳、否决和纠正；重启后的相关任务使用有效版本；各阶段可分别核实。

### F07 · 查看当前认知与行动依据（P0）

- 支持在对话中询问，或进入理解与学习页查看。
- 用日常语言呈现当前相关认知、依据、范围、不确定性、已知反证及失效条件。
- 持久认知、当前任务推断和历史结论明确区分。
- 默认显示理解摘要，不要求用户阅读原始 YAML 或内部协议字段。
- 无数据、未挂载、未加载、陈旧、损坏和读取失败均有明确状态。
- 从解释可以进入证据和纠正路径。
- 活动摘要使用实际可公开事件，不伪造完整内部思考过程。

**完成条件：** 解释能回查到有效状态和证据，异常不编造正常，纠正入口可以完成真实流程。

### F08 · 模型、引擎与身份连续性（P0）

- 持久实体身份与设备、会话、模型及引擎分开。
- 顶栏显示服务端确认的实际模型、引擎与模式；不把用户待选值提前显示成已生效值。
- 模型、推理级别、模式修改走真实配置接口，失败恢复原有效显示。
- 引擎列表动态读取安装、通道、适格性、当前状态及限制，不把静态卡片当可用性证明。
- 切换前核对适格性；有会话时沿用真实 handoff，展示服务端实际阶段，不固定播放七个步骤。
- 切换成功核对实际执行身份、会话、目标、治理与认知连续性；失败明确是否已回到来源引擎。
- 不适格组合正确拒绝；未验证组合保留未验证。不能为取得通过而静默缩小已声明支持范围。

**完成条件：** 声明范围内的模型及重启续接有真实证据；适格切换组合走真实演练；不支持组合能如实拒绝。跨身体夹具通过不等于真实跨身体连续性通过。

### F09 · 客观记录与独立评价（P0）

- 沿用既有好用度客观记账与效力预注册，记录后台完成，不要求主人逐次填表。
- 好用度只采集允许的客观计数、时长和散列；数据留在本地。
- 认知效力记录预测、真实观察与修订，并区分模型内部输出和现实证据。
- 维护、注入、治理及事故处置成本进入既有评价。
- 样本不足、采集失败、缺失维度或尚未完成观察时如实显示。
- 不以消息更少、提案更多、测试全绿或界面更漂亮单独宣称 Personal AI 更有效。

**完成条件：** 本地记录可核对；功能验收、好用度与效力各有独立结论和证据；私有数据不进入公共发布集。

## 8. 前端体验与视觉规范

### 8.1 主工作台

- 主设计尺寸为 1440×900，并验证 1280×800、1024×768。
- 侧栏起点约 240–256px，可折叠；历史标题有明确选中态和长文本处理。
- 正文宽度约 720–840px；详情抽屉约 320–400px，窄窗口改为覆盖式抽屉。
- 顶栏只保留位置、实际运行状态与常用入口，高级参数按需展开。
- 输入区保持可见；不同页面的滚动责任明确。
- 用户向上阅读时新增内容不强制拉到底部；出现新内容时提供回到最新入口。
- 任务建议覆盖问题梳理、资料整理和任务推进，不能将产品默认文案全部限定为编程。

### 8.2 输入与内容

- Enter 发送、Shift+Enter 换行；中文输入法组合期间 Enter 不发送。
- 附件按钮只能展示实际支持的功能，支持类型、读取失败和大小限制来自能力与配置。
- 文本输入自动增高并有上限；长文、代码、表格、路径和引用不破坏布局。
- 发送失败保留输入和重试依据；运行中追加指示与停止是不同动作。
- Markdown 可阅读、可选择、可复制；代码块有语言说明和真实复制反馈。
- 长日志默认摘要化，原文可展开；错误和重要审批不因折叠而不可见。
- 没有实现的按钮应移除或明确禁用并说明原因，不显示无效可点击控件。

### 8.3 设计变量与组件状态

| 设计项 | 要求 |
| --- | --- |
| 风格 | 克制的石墨灰工作台，配套暖白阅读主题；由排版与层级形成质感 |
| 字体 | 系统字体优先；使用额外字体时保证离线回退及中文混排 |
| 正文 | 约 15px、行高约 1.65；以真实中文长内容确认舒适度 |
| 控件与辅助信息 | 控件约 13–14px，辅助信息原则上不小于 12px |
| 间距 | 统一使用 4 / 8 / 12 / 16 / 24 / 32px 尺度 |
| 色彩 | 中性表面、一个主要品牌色；成功、待处理、失败有一致语义 |
| 对比度 | 正文至少 4.5:1；大字号文本、必要图形及控件边界按适用 AA 标准至少 3:1 |
| 圆角与阴影 | 统一尺度；阴影主要说明浮层和层级 |

颜色值在设计输出中冻结为变量，实施时不得在各页面另造一套近似颜色。

### 8.4 可访问性与窗口行为

- 核心流程可用键盘完成，所有按钮和输入有可访问名称，焦点清楚。
- 弹层支持合理的 Esc 关闭和焦点返回；关键审批不能仅靠颜色区分。
- 验证 Windows 125% / 150% 显示缩放，以及文字放大至 200%。
- 窄窗口、长模型名、长路径和长对话下，发送、停止与批准操作仍可到达。
- 离线字体失败和资源加载失败不造成无法操作的空白页；有恢复说明。

## 10. 状态、失败与恢复规则

| 情况 | 界面表现 | 必须执行的行为 |
| --- | --- | --- |
| 配置未知或未就绪 | 明确未知及引导 | 获取配置或进入修复，不能填假模型与假连接 |
| 请求发送中 | 发送中，保留内容 | 等待真实回执，不提前追加成功回复 |
| 请求被拒绝 | 原因和恢复条件 | 不执行，不切入演示成功 |
| 已接收或正在运行 | 当前活动、实际身份 | 消费真实事件，接收回执不能替代最终结果 |
| 等待审批或用户回复 | 突出待处理事项 | 绑定真实请求，过期后不得重新执行 |
| 点击停止 | 停止中 | 核对中止结果后才能显示已停止 |
| 断线或回执丢失 | 连接异常、执行结果待核实 | 先 reconcile，禁止盲目重发副作用 |
| 已完成 | 结果、证据和产物 | 满足完成条件，缺失项明确列出 |
| 产物或认知为空 | 真实空态 | 不填充示例，不宣称已生成或已学会 |
| 引擎切换失败 | 当前实际引擎、失败阶段、恢复结果 | 保持或恢复可信状态，不提前显示目标生效 |
| 恢复遇到后续编辑 | 冲突及可选处理 | 不覆盖后续工作，不把拒绝显示成恢复成功 |

领域状态与连接状态分别维护。后台事件、重复事件、迟到事件和恢复快照需要去重并校验归属。UI 状态名是产品表达，具体映射沿用已有协议，不要求重新命名全部后端枚举。

## 11. 数据、治理与隐私边界

| 数据或机制 | 所有权与规则 |
| --- | --- |
| 权威认知 canonical | 属私有研究与试点，通过配置挂载；不能当普通实例数据搬入产品仓 |
| 会话、草稿、任务与检查点 | 属私有实例；按已有契约持久化、同步与恢复 |
| 认知提案与编译 | 沿用受治理路径；界面发起请求，不直接编辑权威文件 |
| 公开发布内容 | 产品代码、模板、schema、公开 PRD 及获准脱敏衍生物 |
| 凭据 | 使用受保护存储；不进入日志、模型上下文、导出包或截图样例 |
| 健康与诊断 | 标注观测时间与适用设备，不将旧设备快照当当前事实 |
| 评价记录 | 沿用允许字段和窗口，本地保存；公共文档不复制真实消息正文 |

主人拥有目标、价值取舍及授权的最终决定权。认知判断更可靠不产生更高权限。外部模型可能接收任务内容，本地保存不等于推理全程离线；服务对象与相关设置应清楚可见。

## 12. 接线与工程交付约束

### 12.1 复用现有接口

本表是已有实现的接线锚点，不是重新设计协议，也不代表已通过真实使用验收。

| 功能 | 已有接口或机制 | 接入要求 |
| --- | --- | --- |
| 命令与事件 | POST /cmd、GET /events | 统一适配真实响应和事件，不在异常时返回模拟成功 |
| 会话 | session_list / session_new / session_switch / session_history / session_entries | 固定各命令实际字段，加载真实历史，保护会话归属 |
| 任务输入 | prompt 的 message、options；supervisor 的 client_msg_id | 不能用自造 prompt 字段替代 message；不能以缺少 delivered 推断失败 |
| 不确定回执 | prompt_reconcile | 使用既有状态语义，先核对再决定重发 |
| 停止与插话 | abort、steer 的 message | 回执与执行状态一致，停止不只改本地 running |
| 模型与推理 | model_status / model_set / thinking_set | 展示服务端有效值，核对 provider、model、level 等字段 |
| 执行模式 | risk_mode_set、mode_set | 按真实枚举映射产品文案；normal、plan、review 等语义分别核实 |
| 审批 | 既有 ask / 治理请求响应路径 | 在 M0 固定请求 ID、载荷、决定和过期语义；不能自创仅本地生效的回调 |
| 文件变更 | fileops_list / fileops_diff / fileops_restore 等 | 以真实回执关联 Diff 和恢复，不混用导出列表 |
| 导出产物 | /api/artifacts、/api/artifact | 保持既有限定读取范围和失败语义 |
| 引擎 | body_list / eligibility_preview / body_select / handoff_status | 实际阶段来自服务端，安装、适格、执行和连续性分开 |
| 认知 | world_model_status / proposal_decide / proposal_correct / cognition_run | 遵循现有治理、版本和编译路径，明确阶段结果 |
| 健康与评价 | /api/health 及既有记账/评估入口 | 显示已知、未知、陈旧及证据窗口，不能推测为正常 |

会话部分在现有调用中存在不同参数形态；M0 应以有效身体协议、调用方和契约测试共同锁定，而不是照抄任意一处调用。审批字段同样需要在实际请求与响应中核对。

接口适配的参考源码：[HTTP 桥](../app/server/http-bridge.js)、[supervisor](../app/server/supervisor.js)、[host channel](../host/src/core/channel.js)。

### 12.2 前端路径与技术选择

- 复用现有 host、身体与桥，不为美化 UI 重建执行内核。
- 已有 React/Vite 页面是候选界面，不能仅凭组件存在就当作正式交付。
- M0 记录选定 UI 路径、依赖影响与维护成本；重大技术迁移说明对目标的实际收益并遵守已有授权。
- 测试路径与桌面实际加载路径一致；不能用旧 app/ui 的 lint/DOM 通过来验收 app/src / app/dist。
- 选择一条正式产品入口。预览、经典兼容入口和候选构建的身份与用途清楚，不以“目录存在”自动提升未验收候选。
- 不保留会静默改变语义的离线演示兜底。显式预览环境与生产数据、实例、模型、凭据完全隔离。

### 12.3 构建与测试证据

每次交付绑定源码版本或工作区摘要、依赖锁文件摘要、构建产物摘要、实际入口与测试范围。正在运行的版本可核对，旧 dist 不能借用新源码的测试结论。

测试环境沿用 scrub-env 隔离部署挂载；fixture 不得写真实 canonical 或调用真实高成本模型。真实路径验收使用受控工作目录和已授权服务，记录成本与边界。

新界面需要实际覆盖其源码与构建产物的静态检查、组件/契约测试和离屏 Electron 交互测试，并检测对比度、键盘与异常状态。仓库发布前仍执行 AGENTS.md 的完整门禁。

| B02 | prompt 正常接收、拒绝、超时和未知回执 | 分别呈现正确状态；收到 response 不被误判成整个任务已完成 |
| B03 | 发送后立即停止，再注入迟到事件 | 停止可核实；迟到事件归属正确，不恢复已取消执行或伪造成功 |
| B04 | 切换两个会话并重启 | 草稿、消息、审批及运行状态不串线，真实历史可读 |
| B05 | 切模型、推理与执行模式，注入保存失败 | 后端有效值与界面一致；失败不显示已生效 |
| B06 | 批准、拒绝、修改载荷、重复点击与审批过期 | 后端收到正确决定；新载荷重新验证；过期或重复请求不重复执行 |
| B07 | 产物为空、读取拒绝、复制失败、回滚冲突 | 均为真实状态；无演示补位和虚假成功 |
| B08 | 点击新对话建议、中文输入法 Enter | 建议仅填入；组合输入不误发送 |
| B09 | 上滚阅读、长文、代码、表格和路径 | 不强拉到底，内容可选择复制，必要操作可达 |
| B10 | 深浅主题、离线字体、窗口与文字缩放 | 整体主题真实切换并持久化；资源失败可恢复；关键流程可操作 |
| B11 | 键盘、焦点与可访问性检查 | 名称、焦点、弹层返回和对比度达标，关键操作不限于鼠标 |
| B12 | 同一构建从测试与桌面入口加载 | 版本、摘要、资源及 UI 身份一致；不存在旧页面代验新页面 |

### 13.3 证据分类与失败判定

| 证据类型 | 可以证明 | 不能单独证明 |
| --- | --- | --- |
| 静态代码与检查 | 路径存在、语法及规定检查项通过 | 用户能完成真实任务 |
| 隔离 fixture / 故障注入 | 协议、状态、错误和副作用控制符合性 | 真实模型收益或真实跨身体连续性 |
| 视觉与交互记录 | 页面渲染、布局、键盘及具体操作表现 | 任务目标完成或认知有效 |
| 真实路径回执 | 对应版本、组合、任务实际执行结果 | 未覆盖组合与长期效力 |
| 既有规程的评价结算 | 规定范围内的好用度或效力结论 | 规程外的通用能力宣称 |

验收记录包含：需求编号、实际版本、声明范围、真实或模拟路径、前置条件、输入、期望、实际结果、证据位置、结论、限制与恢复条件。

出现假成功、无效停止/审批、重复副作用、错误会话归属、覆盖后续编辑、越权认知写入、私有数据进入发布集，或用错误页面替代正式页面验收，均阻断相关 P0 通过。

未测试、证据缺失与测试失败分别记录。界面可运行不等于整体产品通过。

## 14. 成功标准与评价口径

### 14.1 功能与体验

- 九项 P0 按声明范围完成，A01–A14 与相关 B01–B12 有可核对证据。
- 正式桌面入口、构建产物和被测页面一致。
- 界面布局、主题、内容、键盘与可访问性符合第 8 节。
- 用同内容、同尺寸的前后截图和真实操作记录审查开始、理解、控制与找回结果的负担。
- 本版不新设“5 名用户”“改善 20%”等结算门槛，也不要求主人反复手填评分表。设计反馈可辅助迭代，不能冒充既有评价结果。

### 14.2 本地好用度

沿用[好用度客观记账契约](./usability-ledger-design.md)，不另造一套：

- 滚动 28 天与前一个 28 天比较；每个窗口至少 20 个会话。
- 六项指标：用户轮次中位数、工具错误率、重复用户消息率、大段粘贴率、首响应时延中位数、跨会话重复错误。
- 至少四项改善至少 10%，且无一项退化至少 10%，判为 BETTER；镜像为 WORSE，其余 MIXED。
- 样本不足为 INSUFFICIENT_DATA；规则改变走新版本，旧数据不回溯改判。

以上是摩擦代理指标，不能代替任务质量或认知效力结论。

### 14.3 认知效力与治理

沿用已签收的 Personal AI 试点预注册及其有效版本，不新增实验窗口或更改阈值。按真实观察保留 SUPPORTED / MIXED / UNSUPPORTED / UNMEASURED。

理论覆盖、实现符合性、治理完整性与试点效力分别评价。一次预测—观察—修订、生成提案、身份字段更新或测试通过均不能单独证明效力。

本文件不更新当前效力状态；效力状态从实际记录和规程读取，缺少证据时保持 UNMEASURED，而不是推断为有效或无效。
