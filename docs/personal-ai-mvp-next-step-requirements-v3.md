# Personal AI MVP 下一步需求文档 · v3.0

> 日期：2026-10-15
> 性质：MVP v2.0 交付后的复验修订与下一轮执行需求。
> 当前结论：**本轮未通过产品验收，G1 未达到；G2 本轮未结算。**
> 基线：[MVP v2.0 完整 PRD](./personal-ai-product-mvp-prd-v2.md)。本文件补充修复顺序、接口约束与验收证据，不替代或减少原 F01–F09、A01–A14、B01–B12。

## 1. 本轮结论与下一步目标

用户需要能实际工作的 Personal AI：开始任务、控制执行、找回上下文与产物、管理认知，并知道正在使用的模型、身体和有效认知版本。下一轮要解决的核心问题是：**界面状态和操作效果仍有多处不符合后端事实**。页面数量增加、按钮出现或测试退出码为零，不能解决这个问题。

已确认的进展：

- 命令失败不再统一返回模拟成功；独立断网探针中发送失败有明确提示，没有旧版假完成回复。
- prompt 已使用 message、session_id、client_msg_id；审批、身体选择和文件恢复已有实际命令调用。
- 新增任务、认知、健康和审计页面；modern DOM 测试已明确加载 app/dist，避免仅用经典页面挂载结果代验新版页面。
- 桌面默认 classic，新版需显式选择 modern；候选界面不会仅因 dist 存在自动成为默认界面。

独立复验的阻塞事实：

| 事实 | 用户影响 | 证据 |
| --- | --- | --- |
| session_switch 明确失败后，标题仍显示目标会话，原草稿仍在输入框 | 用户可能误判消息归属，历史与草稿续接不可依赖 | 当前构建故障注入及源码 |
| 工作台模型、推理与模式控件主要只改本地状态；设置的 model_set 缺 provider 或 alias | 显示值可能与执行不符，配置保存可能必然失败 | 源码；模式按钮命令记录 |
| 后端返回 task_id，任务页只读 id/taskId；取消调用不存在的 task_cancel | 有任务却打不开详情，控制动作没有有效契约 | 当前构建契约探针及源码 |
| 身体页不识别真实 body_list/body_current 响应，回退到固定 Pi/DSH 已安装卡片 | 安装、当前身份、能力和切换入口可能误报 | 当前构建契约探针、源码及截图 |
| 审批带命令载荷的分支把“本会话允许”改成单次 allow | 用户选择的授权范围没有正确提交 | 源码 |
| 浅色主题只改局部选中状态，设置页有严重对比度问题 | 主题承诺不生效，部分文字难读 | 当前构建操作、计算样式及 axe |
| modern 门禁返回 ok:true，同时报告 1 类可访问性违规 | 测试通过不能支撑可访问性达标 | 原门禁回执及源码 |

本轮独立复跑 app 测试 **46 项：45 通过、1 跳过、0 失败**，跳过项为 Windows 符号链接权限条件。app lint、仓库 strict 校验与 Skill 质量检查通过，但 lint 仍只覆盖经典 app/ui，modern 门禁主要检查挂载和标题。通过结论只适用于实际覆盖范围。

运行时探针使用本地合成后端；原 modern 门禁使用实际 supervisor/HTTP 桥与 fixture 身体。两者均未调用真实模型、未操作真实 canonical、未执行真实跨身体交接。真实任务产出、认知采纳后使用和长期效力等缺失证据记为“证据未完成”，不能由这些探针补齐。

## 3. 下一轮功能与前端需求

### R01 · 会话切换、历史与草稿一致（阻塞 P0）

**用户结果：** 看到的会话就是后端实际会话，切换失败不会误发，重启后能找到正确历史与草稿。

1. 启动时核对实际当前会话，再读取对应历史；不能仅取列表第一行作为当前会话。复用 session_history/session_entries，固定响应与消息类型映射。
2. 切换按“请求中 → 成功确认并加载历史 → 提交界面状态”处理。明确失败保留原会话、消息、草稿；结果未知先核对实际状态。
3. 切换中阻止向归属不明确的会话发送或审批。迟到历史、事件与回执不得覆盖新会话；按会话、运行和消息身份归属。
4. 草稿至少按实例与会话隔离，新对话有稳定草稿键。保存、恢复、发送成功后的清理不能影响其他会话，重启后仍有效。
5. 新建会话也以后端回执为准，列表、标题、消息、审批、任务与运行状态一致。

**必测：** 两会话独立草稿、切换与重启；切换拒绝、超时、慢历史、迟到事件；核对标题、消息、发送目标与后端。对应 A04/A05、B04。

### R02 · 模型、推理与模式真实生效（阻塞 P0）

**用户结果：** 当前模型和模式可查可改，保存失败可见，未生效选择不会显示成实际身份。

1. 从实际状态接口读取有效 provider、model、推理等级与模式。未配置、未知和读取失败分别显示，不能补默认模型或默认健康。
2. model_set 使用实际要求的 {provider, model} 或已配置的 {alias}，不能只传 {model}。设置与工作台共享真实状态来源。
3. thinking_set 使用真实字段与枚举。产品“计划/执行/审查”文案先映射 risk_mode_set/mode_set 的实际语义；不支持的组合明确不可用。
4. 保存状态包括处理中、已生效、失败和结果未知，以回执及必要回读确认。失败保留上次确认值，不能只改 React state。
5. 身体与模型分别读取；不能猜测 body_current 中有 model 字段。刷新、重启和实际执行仍应一致。
6. provider_add 按实际 {provider, baseUrl, api, model} 契约配置，凭据使用既有 auth_set_key {provider, key} 等有效认证路径；当前设置的 {id, api_key, base_url} 不能当作已生效配置。密钥不进入 URL、浏览器持久存储、日志或发布材料。缺配置、验证失败和服务不可达分别处理。

**必测：** 正常保存、拒绝、非法 provider/model、推理不支持、只读模式；以实际执行记录核对身份与模式。对应 A01/A06/A12、B05。

### R03 · 任务标识、详情与控制遵守真实契约（阻塞 P0）

**用户结果：** 能打开任务、看到真实推进状态，并知道一次控制具体控制什么。

1. 任务以 task_id 为主键，在统一适配层转换 UI 命名；列表、选择、事件、插话和控制保持同一身份。
2. task_events/task_send 等使用命令要求的 {taskId}，不能因字段丢失静默不请求详情。
3. 固定“任务记录/消息邮箱”“当前模型执行”“后台持久作业”的边界；后端未支持时不能承诺后台持续执行或持久恢复。
4. 移除对不存在的 task_cancel 的产品调用，按真实能力提供停止、打断或关闭。先验证 task_interrupt/task_close 各自效果；关闭记录不能说成已停止运行。
5. 控制显示处理中、确认、拒绝、失败和未知；终态、已发生副作用和剩余任务分别说明。迟到事件不得重新启动已停止执行或伪造完成。
6. 任务详情承载目标、约束、完成/未完成事项、下一步、会话、产物与失败原因。有日志不等于完成目标管理。

**必测：** 只有 task_id 的任务、详情失败、空事件、插话失败、重复控制、停止后迟到事件、重启恢复；检查实际效果。对应 A02–A06、B02/B03。

### R04 · 身体事实、适格与交接真实（阻塞 P0）

**用户结果：** 知道哪些身体可用、当前是谁、为何能或不能切换、交接是否实际完成。

1. body_list 当前返回直接数组，含 body_id、label、installed、has_channel、current、facts、eligibility、install_hint；body_current 使用 body_id、runId、sessionId、switching。按有效契约适配，变更同步契约测试。
2. 删除生产态固定 Pi/DSH 已安装、固定 supported 能力及默认 Pi 活动状态。空列表、失败、未知能力分别表达。
3. 顶栏、当前标记与目标 body_id 一致。安装、channel 可用、适格、交接完成和连续性验证分开表达。
4. 切换前核对实际 eligibility，显示原因并禁止不适格切换；发起真实 body_select。进度来自既有事件和 handoff_status，先核对实际事件名、阶段与终态，不自造进度。
5. 超时、断连、启动失败与回滚按实际结果呈现；确认目标接管后才能更新活动标记。上下文连续性须实测。
6. 沿用[支持矩阵](./model-engine-acceptance-matrix.md)并绑定本轮版本；历史矩阵不能直接当作当前运行结论。不适格能力如实拒绝。

**必测：** 仅一种非默认身体、空列表、失败、未安装、不适格、真实交接与回滚。声明支持的组合按 A12 提交真实连续性证据，fixture 只证明协议。对应 A01/A04/A12、B12。

### R05 · 审批范围、载荷与执行一致（阻塞 P0）

**用户结果：** 单次允许、本会话允许、拒绝和编辑操作都准确执行，主人知道具体批准了什么。

1. 保留授权范围；带命令载荷的统一 {answer: allow} 分支不能覆盖 allow_session 语义。
2. 沿用 ask/decision_resolve，核对请求 ID、会话、运行、载荷指纹、范围和过期条件。后端不支持的范围明确不可用，不能换成另一决定提交。
3. 编辑载荷使原批准失效，新载荷重新校验，显示变更后提交正确决定；不能仅替换命令字符串跳过治理。
4. 防重复操作；过期、已处理、错误会话和迟到响应按后端状态处理。隐藏卡片不是执行完成证据。
5. 关联审批回执与后续执行；拒绝、中断、撤销进入客观分类，不自动推导成认知命题为假。

**必测：** 单次/会话允许、拒绝、编辑、重复、过期、跨会话、拒绝回执和回执丢失；核对载荷与实际执行次数。对应 A06/A10、B06。

### R06 · 健康、产物与撤销区分空、失败和陈旧（阻塞 P0）

**用户结果：** 能判断结果是否可信、何时更新、如何恢复；读不到信息不会被解释成正常或没有变化。

1. 区分加载中、有效空结果、有效数据、陈旧、不可用、拒绝、读取失败。fileops_list 失败或坏响应不能转为空数组展示“没有变更”。
2. 健康展示数据时间、观测时间与连接状态；本地请求开始时间不能冒充子系统数据更新时间。
3. 同步按 /api/health 的 available、checkpoint、serverTime 呈现，区分无基线、不可达与旧检查点。备份、治理、认知也按各自证据，不以固定“守护运行中”填补失败。
4. 顶栏健康来自有效观测，初始化未知、断连、陈旧时不能继续无条件显示健康。
5. 列表、Diff、打开、复制、导出和恢复关联真实产物/回执；fileops_restore 按实际 receiptId 等协议执行，失败显示原因和恢复动作。
6. 可逆修改恢复到正确内容；后续编辑不能被覆盖，冲突需保留。完成核对文件与回执，不能只凭按钮反馈。

**必测：** 空、503、拒绝、坏响应、陈旧、真实恢复、后续编辑冲突、打开/复制失败。对应 A07/A11/A13、B01/B07。

### R07 · 补齐可操作的前端体验（原界面 P0）

**用户结果：** 文字可读，已展示控件有效，键盘、输入法、主题与窗口变化不打断工作。

1. 深浅主题覆盖全局、各页、弹层和状态组件并持久化，重启保持；不能只改设置卡片选中样式。
2. 修复已发现 WCAG A/AA 对比度问题，含次要文本、快捷键和页签；正常、悬停、禁用、错误、焦点都检查。
3. 附件按钮若保留，接通选择、类型/大小校验、移除、实际 prompt.options.attachments 和失败恢复。声明不可用时禁用并说明，不留可点无效按钮；不改变原 PRD 必交范围。
4. 保留中文输入法 Enter、Shift+Enter、建议只填入、上滚不强拉到底、长代码/表格/路径复制等 B08/B09 要求。
5. 键盘可导航、发送、停止、审批、关闭弹层并返回焦点；焦点可见、图标有名称、无操作陷阱。
6. 执行 v2.0 第 8 节的布局、字号、间距与窗口要求；探图沿用第 9 节依据，用同内容、同尺寸、同缩放实机前后截图验收，设计稿不能代替实现。

**必测：** 深浅主题与重启、离线字体、原 PRD 尺寸/缩放组合、键盘、输入法、长内容及错误状态。对应 B08–B11。

### R08 · 门禁覆盖新版并能拦下实际失败（阻塞交付）

**用户结果：** 通过意味着声明的行为确实通过，启动界面和被测界面是同一构建。

1. 增加适用 app/src 与构建产物的 JS/JSX、样式和模板检查；保留仍发布的 classic 检查，清楚列覆盖范围，不能用旧 lint 代验 modern。
2. modern 门禁把违反要求的 axe 结果计入失败；缺依赖或执行失败标记未完成，不能静默省略。输出类别、节点与页面。
3. 未处理脚本异常和影响流程的资源/控制台错误进入失败判定；已知环境警告单列理由。开发态 Electron CSP 警告本身不是已证明的攻击，但不能忽略所有错误。
4. 挂载和标题只作冒烟；对 R01–R06 增加命令、回执、状态和失败路径交互断言，必须能拦下本轮缺陷。
5. 绑定源码版本/工作区摘要、锁文件摘要、dist 摘要、UI 模式和资源路径。modern 请求但产物缺失应明确报错或显式提示兼容回退，不能静默改变待验身份。
6. 发布前按 AGENTS.md 执行完整门禁并取得终结回执；中断、仅部分 PASS 行、无最终统计均为证据未完成，不能拼接旧记录宣称全绿。

**必测：** 注入 a11y 违规、未处理异常、关键契约错误，门禁分别失败；修复后通过；门禁与正式桌面同一产物。对应 B11/B12。

### R09 · 日常工作、认知与评价取得真实证据（G1 必需）

**用户结果：** 真实工作完成可核实，学习过程可追踪，产品收益按既有规则评价。

1. F01–F05 在可控目录完成真实多步任务，保留目标、约束、实际模型/操作、结果核查、产物、停止/拒绝和恢复；收到回复或任务状态不能单独证明目标完成。
2. F03/F08 完成重启与跨日续接，恢复未完成事项和预期，核对陈旧事实；声明支持的切换验证连续性及失败边界。
3. F06/F07 分别验证采纳/否决/纠正：来源 → 裁决 → 唯一受治理写者 → canonical 版本 → 编译 → 加载 → 后续使用。逐阶段呈现，proposal_decide 成功不等于全部完成。
4. 否决不得生效；纠正替代旧版本。编译失败、未加载、缺失和陈旧明确展示，解释关联实际有效版本。
5. 复用本地客观记账及 schema，验证身体事件映射、重复摄入处理、客观行、聚合与评价。audit_tail 和健康 JSON 不能代替 F09。
6. 本地账本、真实消息、密钥、会话身份和私有 canonical 不进公开仓，公开材料仅留合成样例与脱敏索引。
7. G1 可在效力 UNMEASURED 时通过，但所有 P0 必须按声明范围完成、治理满足、记录评价链可运行；G2 沿既有签收预注册另行结算。

**必测：** 完整映射 A01–A14，尤其真实任务/续接、认知后续使用、恢复/退出、客观评价。无真实服务或必要授权时先完成隔离修复，真实路径保持“证据未完成”。

## 4. 增量验收矩阵

## 5. 顺序与阶段出口

| 阶段 | 工作 | 出口 |
| --- | --- | --- |
| S0 事实与契约冻结 | 固定候选 UI/构建，补关键响应样例、模式/审批/任务语义和变更范围 | 可复现基线，不扩大功能 |
| S1 交互真实性 | R01–R06；故障注入能拦截本轮缺陷 | 所覆盖契约通过，仍属开发测试 |
| S2 日常工作与界面 | R07/R08；真实 F01–F05 与相关 F08；正式桌面同构建 | 对应 A/B 通过，否则不宣称 M1 |
| S3 认知与记录 | R09 的 F06–F09、全部证据及支持矩阵 | 对应 M2 完成，缺项保持未完成 |
| S4 G1 复验 | 全 P0、界面、治理、完整发布门禁 | 独立验收通过后受控试用 |
| S5 G2 结算 | 按既有认知预注册及好用度契约积累观察 | 规程支持的结论，样本不足如实保留 |

S1 避免用户误判状态与操作；S2 证明界面可承载真实工作；S3 完成 Personal AI 的认知与连续性。它们是原 MVP 的修复顺序，不是替代原目标的更小产品。

本轮不增加页面数量、视觉特效、执行内核或新评价体系作为完成指标。架构/依赖调整须说明解决哪个已确认问题及维护成本；适配层能修的契约问题不扩成无关重构。

## 6. 证据与交付要求

每条记录包括：需求编号、结论（通过/未通过/证据未完成/不适用及依据）、版本/工作区摘要、锁文件与产物摘要、实际入口/UI、真实或 fixture 路径、支持范围、前置条件、输入、期望、实际结果、请求/回执/事件关联、截图/日志/产物、限制与恢复方式。

真实数据保存在实例或私有证据目录，公开仓仅留脱敏索引。至少交付：

1. R01–R09、N01–N22 结果表，映射原 A01–A14/B01–B12。
2. 本轮缺陷回归测试；fixture 与真实路径证据分别列出。
3. 同内容、同尺寸截图，覆盖工作台、任务、身体、健康、设置、审批与异常状态，深浅主题各有关键流程。
4. 正式桌面构建身份和全部必要门禁终结回执，跳过项列条件与影响。
5. 真实任务、恢复、认知版本/后续使用、客观记账/评价私有证据索引。
6. 更新的支持矩阵、限制和 G1/G2 分别结论，缺证据不得写 PASS。

源码、隔离探针、视觉记录、真实操作、长期评价分别支持各自范围；单个请求成功或页面标题不证明上层流程完成。

## 7. 评价口径与变更边界

好用度执行[既有预注册](./usability-ledger-design.md)：滚动 28 天与前一个 28 天，各至少 20 个会话；六项中至少四项改善至少 10%，且无一项退化至少 10%，判 BETTER；镜像 WORSE，其余 MIXED，样本不足 INSUFFICIENT_DATA。六项为用户轮次中位数、工具错误率、重复用户消息率、大段粘贴率、首响应时延中位数、跨会话重复错误。

认知效力沿既有签收预注册，不能用页面、测试数量、一次认知循环或摩擦代理指标替代。缺观察保持 UNMEASURED，不能推成 UNSUPPORTED 或宣称有效。

实施只改直接相关 app、必要契约和测试；host/pi/dsh 变更逐项说明必要性并保持防火墙。运行态/canonical 不进发布仓，fixture 继续 scrub-env 隔离部署挂载。

原交付记录还出现注册表、Skill 目录等范围外操作。独立核对实际 diff、所有权、授权和恢复需求，不能以“前端测试全绿”为由删除、恢复或改写无关包；前端验收与其处置分开记录。
