## 1. 下一轮要达到的结果

用户必须能够依赖界面做真实工作：看到的会话与正文一致，选择的是实际可用模型，停止失败不会被显示成停止成功，选择的附件能够被执行侧读取，健康和身份随实际运行变化，深浅主题真正覆盖工作区。

本轮已有部分修复通过，不再重复要求重做。下一轮先关闭下面明确复现的缺陷，再完成原 PRD 的真实日常任务、认知、连续性与客观评价证据。原 F01–F09、A01–A14、B01–B12 均保留；本文件不能替代原产品目标。

## 3. 下一轮需求包

### D01 · 会话竞争、历史与发送草稿（阻塞 P0）

对应 v3 R01，原 F03/F04、A04/A05、B01/B04。

**结果：** 会话标题、正文、事件、草稿与发送目标始终属于同一已确认会话；失败不丢输入。

1. 为每次会话切换和历史加载建立可核对的请求身份与会话归属。迟到或已失效响应不得覆盖当前界面，可取消旧请求或拒收旧版本结果。
2. 切换期间发送、审批和运行状态不得归属不明；新建、初始化、切换、刷新和重连统一处理。get_state 未确认当前会话时，不能把列表第一行冒充实际会话。
3. 历史读取失败显示错误或保留最后一次已知内容并标记陈旧，不能静默清空成新对话；支持的历史块完整映射，模型元数据缺失显示未知，不能补固定模型。
4. 草稿按实例、会话和新对话身份隔离，切换和重启无覆盖；附件待发送状态同样保护。
5. 发送前保存待确认消息及原始输入。明确未送达后恢复可编辑文本和附件；结果未知保持待核对状态，复用 client_msg_id/prompt_reconcile，禁止盲目重发。
6. 收到接收回执不能单独清除全部恢复信息；确认送达、执行完成与目标完成分开。

**验收：** A/B 历史以相反次序返回；双击切换、慢请求、失败、重连；断网发送与未知回执；实例与会话重启草稿。原正确的“明确拒绝切换”路径必须保持通过。

### D02 · 实际模型目录与能力选择（阻塞 P0）

对应 v3 R02/R04，原 F01/F08、A01/A12、B05。

**结果：** 用户选择后端实际注册且可用的模型及能力，界面不包含生产态 fixture 选择逻辑。

1. 模型选项从 model_list、已配置 alias 或有效目录获得；禁止写死 fake-1/fake-2 或把 fixture provider 作为失败回退。
2. 当前 provider/model/推理/模式来自有效后端状态；未知、不支持、加载中和失败各有状态，不能以固定值占位成实际身份。
3. 保存带 provider/model 或 alias 的真实请求，等待结果并必要回读；只展示已确认值。设置与工作台共享更新，外部变更和身体切换后刷新。
4. 推理等级与模式按实际能力、枚举及语义显示；不能把 low 显示为关闭，也不能把所有非 plan 状态统称执行。
5. 保留已修正的 provider_add/auth_set_key 接线，验证正常与拒绝路径。密钥不进入持久浏览器存储、日志或公开材料。
6. 历史消息显示其实际执行身份；未知时标明未知，不把当前模型或初始化默认值附会到旧消息。

**验收：** 仅提供两种非 fixture 默认模型，用户可选择两者；非法/过期模型拒绝；保存失败、设置页与工作台一致、刷新/重启、推理不支持。需要真实模型的 A01 最后单独验证。

### D03 · 停止与任务控制真实反馈（阻塞 P0）

对应 v3 R03/R05，原 F02/F04、A03/A05/A06/A10、B03/B06。

**结果：** 停止失败可见，用户仍能控制真实运行；任务状态读取失败不冒充空结果。

1. abort 显示“请求停止 → 确认停止 / 拒绝 / 未知”，不能无条件 setRunning(false)。拒绝时保留运行控制和原因；超时先核对，晚到事件按运行身份处理。
2. 区分停止当前模型执行、打断绑定作业、关闭任务邮箱；按实际回执陈述，未绑定作业时明确不可用或说明原因。关闭任务不等于停止全部后台工作。
3. task_events 失败/拒绝/坏响应显示读取失败；保留上次成功详情并标记陈旧，或显示未知，不能呈现“尚无事件”。列表和详情时间、任务身份一致。
4. 任务控制处理中防重复，终态从真实状态确认；迟到结果不覆盖新任务，轮询离开页面即清理。
5. 审批保留本轮已修授权范围，补编辑后重验、重复、过期、错误会话和回执丢失。审批成功与后续执行结果分开，人类拒绝/中断不自动变成命题为假。

**验收：** abort 拒绝与超时、实际停止后无继续副作用；无绑定作业、任务详情失败、关闭与打断的各自效果；审批完整负例。

### D04 · 附件传输到可读取内容（阻塞已展示功能）

对应 v3 R07，原 F01/F02、B01/B02。

**结果：** 被选中的文件内容进入受支持的附件链，失败可恢复，不能只有附件名称。

1. 沿用现有附件协议，提供实际 data/path/url 来源及正确 bytes/mime；可用受控上传或受支持的内联编码，不要求新增无关存储系统。
2. 文件路径只能来自安全且可核对的选择/上传结果，不能信任浏览器 filename 就可读服务器同名文件。模型实际能读到已选内容才算成功。
3. UI 与后端对齐大小边界：当前 UI 放行 10 MiB，而真实规范上限为 8 MiB；按真实能力统一提示、校验和总请求上限。类型、内容、编码错误与不支持能力有明确反馈。
4. 文本、图片及其他媒体按已有能力区分原生读取、明确描述降级与拒绝；不能假装读取或转写不支持内容。
5. 待发送、上传中、可用、发送失败、未知与移除状态可见；失败不清除原文件选择和恢复引用，不把浏览器 File 对象仅序列化成元数据。

**验收：** 选择含唯一内容标记的文件，执行侧可核对内容；缺源被拦截；边界大小、坏内容、失败重试、附件独立发送与重复副作用。纯函数合规证据和真实读取证据分别提交。

### D05 · 健康与身体事件同步（阻塞 P0）

对应 v3 R04/R06，原 F04/F07/F08、A11/A12、B01/B12。

**结果：** 界面准确显示健康、活动身份、交接阶段与未知状态。

1. 分开传输成功与业务健康。治理按实际 ok/lanes/overdue/错误判断；读取失败不能显示正常。认知读取失败、未编译、已编译、未加载与已使用分开。
2. 顶栏初始为待确认，断连和陈旧按事实变更；健康页与顶栏共用有效观测，不能始终保留默认“健康”。
3. 数据时间、观测时间、有效期分别说明；请求开始时间和 health.serverTime 不能充当所有子系统数据更新时间。同步按 available/checkpoint 的实际语义区分无基线、不可用、损坏和旧记录。
4. 订阅实际 supervisor 事件：handoff_phase 的 phase 字段、select_start/select_done/select_failed、body_exited/body_respawned 等。阶段名和终态以现有协议及 handoff_status 确认，不凭大写自造事件。
5. 交接后同步顶栏、身体页、模型、会话与运行身份；失败显示实际原因和回滚结果。只有 confirmed active 才显示接管完成。
6. 保留本轮 body_list/body_current 事实解析和无固定卡片回退；不适格原因、能力未知与未安装准确呈现。

**验收：** 外层 success:true、内部 ok:false；断网、陈旧、损坏、未加载；按真实事件名注入阶段、失败与重启；声明支持的实际交接按 A12 另取证。

### D06 · 全局主题与可操作工作台（原前端 P0）

对应 v3 R07，原 B08–B11。

**结果：** 深浅主题覆盖工作区，提示可读，建议由用户确认发送，长内容和键盘操作不打断工作。

1. 将实际背景、文字、边框、弹层和状态组件绑定主题 tokens，替换阻止主题生效的硬编码颜色；仅切 data-theme 或 CSS 变量不算通过。
2. 深浅模式均覆盖各页面、审批、错误、禁用、悬停和焦点，保存并重启后保持。用实际计算样式和截图核对。
3. 修复浅色设置页发现的 serious 对比度问题，并逐页检查全部主题/关键状态，不能用末尾聊天页 axe 为零代表全局通过。
4. 空对话建议只写入输入框，保留编辑权；用户明确发送前不能发起 prompt。
5. 上滚阅读时不强制滚到底；中文输入法、Shift+Enter、长代码/表格/路径、选择复制、键盘焦点和窗口缩放继续执行 v2 要求。
6. 探图参考沿用 v2 第 9 节，不用新增视觉稿替代功能修复。交付同内容、同尺寸、同缩放的前后实机截图，包含深浅主题和失败态。

**验收：** 实际颜色改变、各页与重启、建议点击零 prompt、输入法、键盘全流程、上滚保持位置、窗口与长文；自动可访问性加人工流程核对。

### D07 · 测试隔离与能拦下缺陷的门禁（阻塞交付）

对应 v3 R08，原 B11/B12。

**结果：** app 检查可重复，用户真实配置不会改变测试结果，本轮关键缺陷复发时必须失败。

1. desktop-options 测试显式指定临时 instance，所有配置由 fixture 创建。分别测试无配置、配置 modern、CLI/env 优先级；不能删除真实配置或放宽正确断言使测试变绿。
2. 保留 scrub-env；测试禁止启动真实 canonical 或 provider。临时实例、HTTP/SSE、轮询与子进程都有负责人和清理。
3. axe 缺失、执行失败和违反要求均阻断；按每页、主题和关键状态运行。零违规声明标明检查页面及状态，不省略未覆盖项。
4. 未处理异常与影响流程的资源/控制台错误进入判定；开发态 CSP 等已知环境警告单列，不把警告直接推为攻击，也不忽略所有错误。
5. 加入 D01–D06 的业务回归及负向对照：迟到历史、停止拒绝、附件缺源、假健康、主题不生效和自动发送建议等必须让门禁失败。
6. Vite build 保留为构建检查，补适用 modern 源码的静态检查；不把构建成功标成语义正确或完整 lint。
7. 正式启动绑定源码/锁文件/产物摘要、UI 模式、入口与声明范围。保留 modern 缺产物显式错误，实际桌面与测试同构建仍须验证。

**验收：** 本机有不同配置时测试仍确定；注入上述缺陷门禁失败，修复后通过；完整日志和终结回执可核对。

### D08 · 完整产品真实证据与评价（G1 必需）

对应 v3 R09，原全部 F01–F09、A01–A14 与相关 B。

1. 完成真实配置、目标与约束保留、多步任务产出、结果核查、停止/拒绝、文件撤销冲突、恢复与退出预览。完成任务以目标和产物依据确认，不能仅凭消息到达。
2. 跨日与重启恢复未完成事项和预期，核对陈旧事实；声明支持的模型/身体范围各有真实证据和限制。
3. 认知采纳、否决、纠正分别记录来源 → 裁决 → 唯一受治理写者 → canonical 版本 → 编译 → 加载 → 后续使用。否决不生效，纠正正确替代旧版本。
4. 复用本地客观记账与评价入口，核对当前身体事件映射、去重、客观 schema 和真实报告；审计列表不替代 F09。
5. 真实消息、会话身份、密钥、账本和私有认知留在实例或私有证据目录；公开仓只放合成样例、脱敏索引与需求。
6. G1 要求全部 P0 与前端要求按声明范围通过、治理有效、记录评价可运行。效力仍可 UNMEASURED；G2 按既有签收预注册另行结算。

真实服务或必要授权缺失时，先完成隔离修复和可验证准备；对应真实用例保持证据未完成，不能改写为通过。

## 5. 执行顺序与检查范围

1. 先修 D01–D05 的状态、控制和内容传输，补能复现本轮问题的回归；保留已确认修复，不重建执行内核。
2. 完成 D06 的全局主题与工作台交互，以及 D07 的隔离、负向对照和同构建验证。
3. 完成 D08 全部真实路径，映射原验收矩阵；独立复验通过后再宣布 G1。
4. G2 按既有规程持续取证与结算，不能用功能测试代替效力观察。

按用户最新 AGENTS 精准执行检查：

| 本轮实际改动范围 | 必要检查 |
| --- | --- |
| 仅 app | app lint 与 app test；新增对应业务/故障用例 |
| 涉及 host/pi/dsh | 只增跑实际修改层及受影响契约，pi 未改不跑 pi |
| 涉及结构、注册表、基础脚手架 | strict 校验与 diff 空白检查 |
| 仅需求或报告文档 | 链接、编号、格式、公开边界与摘要检查 |
| 整仓发版或 PR 合并前 | 按最新 AGENTS 执行完整发布合入门禁 |

日常局部验收不要求无关全仓回归。完整发布门禁只在实际发版/PR 合并时执行；本轮缺陷不能通过修改无关 Skill、注册表、真实用户配置或降低断言消除。

## 6. 交付物与评价边界

交付需求/原用例映射表、改动范围、失败回归、逐页深浅截图、同构建身份、真实与 fixture 分开的日志及回执、真实任务/认知/记账私有证据索引、限制与 G1/G2 分别结论。

每条证据注明版本、源码/锁文件/构建摘要、入口、前置条件、输入、期望、实际、请求/事件/回执关联、结论及恢复方式。“通过”“未通过”“证据未完成”分别使用，不把源码接线当真实工作完成。

好用度继续按[既有契约](./usability-ledger-design.md)：28 天对前 28 天，各至少 20 个会话；六项中至少四项改善至少 10% 且无一项退化至少 10% 为 BETTER，镜像 WORSE，其余 MIXED，样本不足 INSUFFICIENT_DATA。六项指标及定义不变，规则变更走新版本，不回溯改判。

认知效力沿既有签收预注册；没有观察保持 UNMEASURED，不能推为 SUPPORTED 或 UNSUPPORTED。一次循环、测试通过、页面增加、视觉改善都不能代替效力结论。
