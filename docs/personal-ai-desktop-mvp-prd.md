## 1. 产品定位与长期目标

**Personal AI 是一个能跨时间和会话持续合作的个人 AI：理解主人的目标与现实状态，选择并推进下一步，从真实结果中发现错误、修订认知，并保持主人的最终决定权。**

它通过可替换的模型完成推理，通过可替换的执行引擎调用工具。经历、认知、价值、治理和身份连续性分别保存和维护，使合作不依赖某一次聊天或某一个模型。

长期目标是：**在维持结果质量、可靠性与权限边界的前提下，减少主人不应承担的认知劳动，并约束时间、计算和维护成本。**

主人不应反复承担恢复状态、搬运提示词、催促继续、替 AI 查证可自行核实的事实、识别虚假完成和修复目标漂移的工作。价值取舍、必要授权和真正无法安全获取的信息，仍由主人判断。

### 1.1 产品中几个对象的分工

| 对象 | 回答的问题 | 产品含义 |
| --- | --- | --- |
| 记忆与证据 | 发生过什么，来源在哪里？ | 保留经历和可回查依据 |
| 世界模型 | 哪些规律和因果解释目前成立？ | 支持预测、反事实判断、错误定位和行动选择 |
| 价值状态 | 什么值得做，哪些约束必须保留？ | 服务目标与取舍，不把事实判断混成价值决定 |
| 治理 | 谁能批准什么，认知和规则如何修改？ | 保留主人的规范权威，约束自我修改 |
| 身份连续性 | 换会话、模型或身体后如何续接？ | 保持实体、认知版本与经历的可识别连续性 |
| 推理与行动机制 | 如何使用上述状态完成工作？ | 使用模型、技能、工具和执行引擎推进真实任务 |

世界模型保存可使用、可检验的结构；记忆保存实例和证据。短摘要保留回查入口，不能成为丢失边界后的唯一事实来源。

## 2. 用户、需求来源与核心问题

### 2.1 主用户

当前主用户是主人本人：技术能力较强，长期处理本地工程、文档和研究工作，使用多个项目和设备，希望 AI 持续推进工作，也保留检查、纠正和停止的权利。

公开产品保持可独立安装与采用的最低条件。多用户体验、市场和商业化不属于本版设计投入。

### 2.2 已确认的需求锚点

本版从项目发展和原始需求中承接以下要求：

1. 在已有真实项目中应用，优先使用自然产生的任务与反馈。
2. AI 负责读取、维护和推进，主人正常提出目标，无需填写认知流程模板。
3. 跨会话保留未完成事项、重要预期和修订依据，压缩后仍能恢复必要上下文。
4. 各项目共享方法与协议；领域事实、人物判断和一次性授权不得自动跨项目传播。
5. 认知需要能被经验纠正，并在后续判断或行动中体现。
6. 用真实结果和预先约定的规则评价收益，维护机制本身也接受成本与效果检验。

### 2.3 主人要完成的五个任务

| 编号 | 用户任务 | 产品成功标准 |
| --- | --- | --- |
| T1 | 新设备或坏设备上恢复使用 | 复用既有入口，一句话启动、一次报告说明结果；环境与账号条件具备时，沿用 30 分钟恢复目标 |
| T2 | 每天直接用 AI 干活 | 打开应用交代目标，AI 持续推进，交付可核实结果；主人不必理解内部机制 |
| T3 | 确认 AI 当前状态正常 | 打开应用后 3 秒内看到健康状态区域，包括运行、最近同步及已取得的各平面状态；未取得的信息显示未知 |
| T4 | 看见新认知并纠正 | 能看提案和依据，采纳或否决；已生效认知可以经治理纠正，并验证后续行为 |
| T5 | 理解 AI 当前信什么、为什么这样做 | 用日常语言查看相关认知、约束、依据、不确定性和未解决事项 |

30 分钟与 3 秒沿用现有任务标尺。其余性能数值先测量再设门槛，不在本 PRD 新增未经依据的百分比、时长或样本要求。

## 3. 当前基础与 MVP 切入点

### 3.1 沿用的基础

仓库已存在以下代码、协议或工具入口。此表记录可复用基础，具体功能是否可用仍以对应版本的真实路径验收为准。

| 基础 | 现有承载 | 本版处理 |
| --- | --- | --- |
| 自有桌面入口与对话 | app、桌面壳、会话与模型配置 | 收口日常工作路径，核实显示配置与实际执行一致 |
| 统一治理与执行 | host、Pi/DSH 适配、审批、预算与租约 | 沿用权威执行链，不新增旁路 |

| 文件与结果控制 | 变更回执、产物、备份、差异和恢复 | 给出可理解结果，验证撤销与冲突保护 |
| 认知维护 | soul 契约、mind 工具链、身体适配器 | 接通证据、提案、裁决、编译与后续消费 |
| 认知与健康界面 | 状态、认知查询、提案裁决相关入口 | 明确空态、失败、陈旧、生效与待裁决的区别 |
| 设备生命周期 | bootstrap、同步、备份、卸载入口 | 复用既有链路，核实私有资产与认知边界 |
| 效果评估 | 认知效力预注册、本地好用度记账 | 沿用已签收规则，分别报告效力与摩擦变化 |

既有多引擎、调度、委派和其他能力继续按既有契约管理；本 PRD 不将它们重新定义成未来功能。

### 3.2 本版要解决的关键未知

MVP 选择一条贯穿日常工作的闭环：

```text
主人提出真实目标
  → 恢复相关状态与有效认知
  → 判断当前问题及下一步
  → 推进已授权行动
  → 观察实际结果与主人的反应
  → 识别失配，形成有依据的认知提案
  → 主人经治理裁决
  → 更新后的认知被后续任务实际使用
  → 按预注册规则评价收益与维护成本
```

这条闭环用来回答三个问题：

- 持久认知是否真正参与下一步选择，而非只被保存和展示？
- 发现错误并修订后，后续相关任务是否减少同型错误或重复分析？
- 这些收益是否足以抵偿新增的运行、治理和维护负担？

普通小任务直接完成；重要判断按需维护可检验的预期和结果。任务形式由实际问题决定。

### 3.3 MVP 范围

P0 表示本版必须闭合的产品要求，既可由已有能力满足，也可通过必要增量完成。

| 类别 | 范围 |
| --- | --- |
| P0 | T1–T5 的可用路径；目标与状态理解；当前项目内有理由的下一步选择；授权内持续推进；真实结果核实；跨会话继续；停止、审批和恢复；认知查看、裁决、纠正与后续使用；既有评估接入 |
| 现有能力的验收 | 实际声明支持的模型、引擎、调度、委派和切换组合，逐项给出证据与限制 |
| 后续增量 | 新引擎、新平台、更多领域适配、更复杂的跨项目规划与高级分析；由真实缺口和收益证据决定 |
| 本版不新增 | 多用户组织体系、插件市场、移动端、云端托管工作区、完整 onboarding 向导、全知世界模型、自动取得更高治理权限 |

模型与引擎的覆盖范围通过版本验收矩阵声明，不以界面存在选项推定支持，也不在本 PRD 硬编码成某一个引擎。

## 4. 核心用户流程

### 4.1 完成真实任务，并在隔天续接

1. 主人打开工作目录，用自然语言提出目标与交付要求。
2. AI 恢复相关目标、约束、有效认知和最近实际进展；核对可能变化的状态。
3. 对明确的下一步直接推进；多个合理对象无法区分时再请主人选择。
4. 需要批准时展示具体影响；普通已授权工作不中途反复请求“是否继续”。
5. 交付结果、产物入口和验证结论，明确剩余事项。
6. 重开应用后续接未完成工作，先核对上次执行结果，避免重复副作用。

### 4.2 发现同型失配，形成可纠正认知

1. 真实工作产生结果，与事前预期比较，记录符合或失配。
2. 区分环境变化、证据问题、实现错误、适用范围错误与模型错误。
3. 按已声明的学习触发与治理规则复查；不把一次结果直接升级成稳定规律。
4. 有充分依据时提出候选认知，展示其来源、范围、反例和失效条件。
5. 主人采纳、否决或提出修正；裁决状态与持久写入结果可分别核实。
6. 后续相关任务读取有效版本，验证是否改变判断、行动或错误复发情况。

### 4.3 主人中断、拒绝或撤销

1. 主人可以立即请求停止、拒绝审批，或撤销受管理的可逆改动。
2. 系统说明动作是否停止、哪些改动已经发生、哪些可以恢复。
3. 保留反馈发生的对象、上下文和结果。
4. 区分授权决定、临时偏好、目标改变和对事实的纠正；不将“拒绝执行”自动解释成“模型命题为假”。
5. 必要时调整当前工作；涉及持久认知或规则时走相应治理路径。

## 5. 功能需求

### F01 · 就绪、恢复与退出（P0，T1/T2）

**用户结果：** 能从桌面进入工作，在环境损坏或换设备后恢复，并知道恢复结果。

- 选择工作目录、配置模型服务与凭据、测试连接，并选择实际使用的模型。
- 已有效配置可复用；失败显示真实原因和可执行的恢复动作。
- 沿用 bootstrap、同步与备份恢复入口，报告通过、失败、跳过、未知及所需处理。
- 工作目录切换前说明会话与执行影响，保护输入和进行中的工作。
- 卸载先给出范围预览，实际移除按既有授权执行；权威认知、会话和凭据不混入组件卸载清单。

**验收：** 从真实桌面入口完成配置与真实消息往返；显示模型与实际执行一致；完成一次受控恢复演练；卸载预览能清楚区分组件和私有资产。

### F02 · 理解目标并持续推进（P0，T2）

**用户结果：** 交代目标后，AI 能承担合理的执行与判断工作，直到完成或遇到真实边界。

- 保存最终目标、必要约束、交付物和完成条件；目标变更有明确记录。
- 当前状态至少区分有效事实、历史观察、当前推断和未知，并保留来源与观测时间。
- 在当前项目或目标范围内，依据相关性、依赖、信息价值、风险与成本选择下一步。
- 有多个未完成事项时说明选择理由；价值优先级实质冲突时交由主人裁定。
- 在授权内持续执行，使用已有工具、目标协调和调度能力；不为证明推进而制造任务。
- 失败改变后续判断，必要时调整方法；不能静默缩小目标或把中间产物当最终完成。
- 模型或引擎变更遵循显式选择与既有路由政策；发生已授权回退时显示实际执行身份和原因。

**验收：** 用一个真实目标走通多步工作；包含多个未完成事项时，下一步选择与目标有可说明的关系；工具失败、证据缺失或目标未满足时不宣称完成。

### F03 · 跨会话状态与未完成事项（P0，T2）

**用户结果：** 重开应用或换会话后，AI 能接棒，不要求主人重新搬运已有背景。

- 保留目标、已确认约束、真实进展、未完成事项、待观察的预期和结果指针。
- 恢复任务相关内容，并按影响核对可能过期的文件、环境或外部状态。
- 压缩后的状态保留关键边界、修订理由和原始依据入口；不能通过摘要补造事实。
- 跨项目复用遵守领域覆盖声明，共享方法不等于共享所有事实。
- 恢复前核对动作是否已执行；断线、超时和重试不得重复提交有副作用的动作。
- 一次性授权不转成永久授权，已结束或已失效的许可不能在新上下文中自动复活。

**验收：** 跨日续接真实任务；重启后能恢复未完成事项及预期；模拟回执丢失后正确核对结果，没有重复写入或外部操作。

### F04 · 运行状态、停止、审批与健康（P0，T2/T3）

**用户结果：** 随时知道正在发生什么，能控制继续、停止与授权。

- 区分准备就绪、运行中、等你回复、等你批准、受阻、停止中、已停止、失败与已完成。
- 状态绑定实际执行与回执；不虚构进度百分比、剩余时间或停止成功。
- 运行中提供唯一、醒目、可访问的停止入口；确认停止前保留“停止中”状态。
- 停止阻止后续动作，已经完成的改动另行说明；无法确认停止时显示不确定。
- 审批发生在动作之前，展示对象、影响、权限范围和不可恢复部分，允许批准或拒绝。
- 危险操作遵守既有分级确认；已授权的常规操作不新增重复批准。
- 健康区显示已取得的连接、运行、同步和各平面状态及观测时间；陈旧、缺失、损坏和读取失败分别呈现。
- 故障保留输入，给出恢复入口。守卫拒绝时说明原因与恢复条件，例外仅走既有显式审计路径。

**验收：** 停止与拒绝确实阻止后续执行；断线重连不丢输入、不重复副作用；陈旧或缺失健康信息不显示成正常。

### F05 · 真实结果、产物与后悔权（P0，T2）

**用户结果：** 能判断工作是否做成，打开产物，并恢复受管理的可逆改动。

- 结果首先说明做成了什么、依据是什么、仍缺什么和下一步责任。
- 文件、报告、执行记录等提供可打开入口；验证结论区分已验证、未验证和失败。
- 将技术原料换算成与目标相关的影响说明；原始 diff、日志和回执按需展开。
- 对支持恢复的文件操作保留改动前状态，提供单项撤销与对应版本依据。
- 撤销前检查后续编辑与并发冲突；存在冲突时停止覆盖并说明选择。
- 不可恢复的动作事前明确，不展示虚假的撤销承诺。

**验收：** 真实产物可打开且符合完成条件；可逆改动恢复正确；后续编辑受到保护；测试通过、产物生成和任务目标实现分别说明。

### F06 · 认知产生、裁决与纠正（P0，T4）

**用户结果：** 看得见学习过程的结果，能阻止错误认知生效，并纠正已生效认知。

- 收集真实任务结果与主人反馈，保留来源、对象、时间、证据类型和适用范围。
- 模型内部推演、未经回放的过程和自我评审不能冒充新的世界证据。
- 一次性要求、授权、偏好、事实纠正与方法命题分别处理；当前任务修正不必等待长期提案。
- 候选认知须有可回查依据，说明稳定性、适用范围、行动意义、不确定性及推翻条件。
- 按已声明的触发规则处理结构性复发或高影响失配；调度运行本身不构成学习证据。
- 定时维护或“立即提炼”可以复用既有入口；没有满足条件的证据时，不制造提案或学习成果。
- 提案可采纳或否决，也能提出修正；没有明确期限、退出和恢复语义时不提供“试用”。
- 已生效认知经治理纠正、替代或回退；保留原因、版本与历史，界面和对话代理不直接写权威状态。
- 明确区分已生成提案、裁决成功、持久写入、编译完成与后续实际使用，失败停在哪一段可见。
- “本周新增”区分候选、生效与修订，数量只作信息，不作认知进步结论。

**验收：** 在真实任务证据上形成候选，完成采纳、否决和纠正路径；重启后的相关任务使用正确版本；否决或已替代内容不作为现行认知继续执行。

### F07 · 查看当前认知与决策依据（P0，T5）

**用户结果：** 能理解 AI 当前的判断，并知道如何质疑或修正它。

- 支持询问当前项目理解、行动依据、适用限制和不确定事项。
- 以日常语言呈现相关认知、支持依据、观测时间、最强已知反证或失效条件。
- 持久认知、任务内推断和历史结论明确区分；默认不展示原始 YAML 和内部协议字段。
- 依据可回查，未解决事项可续接；无记录、未加载、陈旧和读取失败分别呈现。
- 无数据时不编造认知，无新观察时不宣称已现场确认或已学习。

**验收：** 回答可追溯到有效状态与证据；遇到空态、陈旧或读取失败能诚实呈现；主人可从解释中进入相应纠正路径。

### F08 · 实体连续性与实际执行身份（P0，T2/T4/T5）

**用户结果：** 能确认谁在执行，并在声明支持的变更后继续原有合作。

- 将持久实体身份与会话、设备、模型、执行引擎分离。
- 正常重启与新会话恢复有效认知、目标和治理约束。
- 模型或引擎切换走既有适格性、交接和绑定路径；失败不显示成成功。
- 模型与引擎验收矩阵同时声明可配置、适格、真实执行通过、连续性已验证及限制。
- 身份元数据更新、运行进程加载和跨身体连续性分别取证。
- 没有真实切换证据的组合标为未验证，不能用模拟身体或绑定字段替代真实连续性结论。

**验收：** 重启和新会话连续性通过；对本版声明支持的切换组合进行真实演练，核对目标、认知、治理与执行身份；不支持的组合明确拒绝或保留未验证状态。

### F09 · 客观记录与效力证据（P0，T2–T5）

**用户结果：** 能依据真实使用判断产品有没有变好，而非依赖 AI 自述。

- 认知效力与日常使用摩擦分别评价，使用各自已签收的规则、窗口与状态。
- 采集和评估在后台运行，不要求主人维护状态表、手工搬运日志或逐次填写评分表。
- 好用度记账只保存允许的客观计数、时长和散列；数据留在本地，不含消息正文与自由文本。
- 认知效力记录真实预测、观察与修订，区分现实证据和模型内部输出，并保留评价知情度等解释条件。
- 维护、注入、治理及事故处置成本进入评价；按既有成本规则触发复查。
- 数据不足、采集未就绪或维度未覆盖时如实显示，不反向改口径制造收益。

**验收：** 本地记录可核对，私有数据不进入发布集；能给出独立的效力与摩擦报告，并说明样本、窗口、缺失与限制。

## 6. 界面与交互要求

### 6.1 信息结构

| 表面 | 首要内容 |
| --- | --- |
| 当前工作 | 对话、输入、任务结果、运行状态；停止和待批准事项就地可见 |
| 最近工作 | 会话与未完成任务入口，支持续接和查找 |
| 认知 | 待主人裁决的提案、当前有效认知、修订记录和依据 |
| 健康区 | 连接、执行、最近同步和可取得的平面状态 |
| 设置 | 模型服务、凭据、工作目录和当前引擎 |
| 按需详情 | 产物、文件差异、回执、诊断和安全记录 |

认知查看与裁决可从当前工作进入，不要求主人先进入内部监控或阅读架构说明。

### 6.2 设计原则

1. 按主人必须承担的判断排序：停止、批准、撤销和认知裁决获得足够视觉优先级。
2. AI 能解释和代劳的操作优先由对话完成，不为每个内部模块增加页面。
3. 结果给出与目标有关的结论，原料按需展开，避免把大量日志交给主人作验收。
4. 用结构、位置、形态和状态反馈说明操作；故障态与不可逆操作直接说明现状和出路。
5. 状态不只靠颜色，关键控件支持键盘和可访问名称。
6. 未配置时提供必要连接表单，日常工作不依赖多步教学向导。

## 7. 状态与失败处理

| 情形 | 系统行为 | 用户可采取的动作 |
| --- | --- | --- |
| 模型不可达或配置无效 | 保留输入，显示连接原因与实际配置 | 测试连接、修正配置或按既有政策切换 |
| 请求发出但回执丢失 | 标记结果待核对，先查执行结果 | 查看核对结果，再决定续接 |
| 状态陈旧或多来源冲突 | 显示来源时间，暂停依赖该事实的高影响动作 | 允许核验，或裁定无法消除的冲突 |
| 任务受阻 | 说明阻塞对象、已有证据和必要恢复条件 | 补充不可获取信息或作必要决定 |
| 认知提案被拒绝 | 保留裁决记录，阻止进入现行认知 | 提出新证据或修正提案 |
| 编译或加载失败 | 保留既有有效版本与明确失败状态，不假报生效 | 重试既有恢复路径或查看诊断 |
| 撤销遇到后续编辑 | 阻止覆盖，显示冲突范围 | 选择保留、合并或放弃撤销 |
| 无足够效果证据 | 分别报告 UNMEASURED 或 INSUFFICIENT_DATA | 继续真实使用并按既有规则积累 |

AI 对错误的解释必须与观察分开。拒绝、停止和撤销是重要反馈，其事实、意图与认知含义不能自动混为一个结论。

## 8. 数据、治理与隐私边界

### 8.1 所有权与存放

| 层 | 内容 | 规则 |
| --- | --- | --- |
| 私有研究与试点 | 理论、试点 Adapter、权威认知状态 canonical、治理预测和修订历史 | 由研究与试点仓持有，产品通过配置挂载；权威认知不放入实例根 |
| 公共产品仓 | 产品代码、机制、模板、schema 契约、脱敏认知衍生物与 PRD | 不包含真实会话、私有认知、密钥、设备路径或运行记录 |
| 私有实例层 | 会话、运行记忆、任务状态、检查点、运行 ledger 与运行预测/观察 | 按实例契约持久化与同步，不混入研究 canonical 或公共发布集 |
| 设备运行层 | 缓存、索引、设备健康快照和临时诊断 | 服务本机，不作为跨设备权威事实，不发布 |
| 凭据存储 | 模型与外部服务凭据 | 使用既有受保护存储；认证以外不回显、不写日志、不进入模型上下文或发布包 |

“私有”不等于“都放在同一个目录”。治理预测与运行预测遵守各自所有权，不能因为同名而混用。

### 8.2 治理与外部服务

- 主人拥有目标、价值取舍和执行权限的规范权威，认知判断更可靠不产生更高决定权。
- 权威认知变更沿用受治理提案、验证与接受路径；产品界面不能通过编辑原始文件绕开它。
- 公开衍生物只经既有脱敏链产生；跨设备同步沿用现有所有权、身份和冲突规则。
- 选择外部模型服务时明确服务对象；任务所需内容可能发送至该服务。本地保存不等于推理全程离线。
- 费用只在有可靠依据时展示；否则报告可得用量并标记费用未知。新增服务或扩大高成本范围遵守已有授权。

## 9. 成功标准与评价规则

### 9.1 四种结论分别报告

| 评价对象 | 应回答的问题 | 结论边界 |
| --- | --- | --- |
| 理论覆盖 | 当前理论是否处理所声明范围的问题类别？ | 开放问题与遗漏分别记录 |
| 实现符合性 | 实现是否满足声明支持的机制和约束？ | 按具体版本、范围与证据给出通过或失败 |
| 治理完整性 | 是否越权、自证、后验改写或发生来源漂移？ | 对相应修订、准入和治理事件单独评价 |
| 试点效力 | 真实使用是否获得预声明的收益？ | SUPPORTED / MIXED / UNSUPPORTED / UNMEASURED |

每条结论绑定对象、版本、范围和证据窗口。发布准入可以依据这些结论作政策决定，不能将它们合成一个“已证明聪明”的总分。

### 9.2 认知效力

沿用已签收的 Personal AI 试点预注册，不在本 PRD 新建另一套效力实验或更改阈值。

| 维度 | 当前选测 | 观察内容 |
| --- | --- | --- |
| 更好的预测 | 选测 | 已登记预测与真实观察的结算情况 |
| 更少的重复分析 | 选测 | 有效认知在后续任务中的复用与无必要重复分析 |
| 更清楚的错误定位 | 必选 | 失配能否定位到证据、事件、规律或元模型层及其来源类型 |
| 更可靠的修订 | 必选 | 修订记录完整性、修订层级与同型失配复发情况 |
| 更好的迁移 | 本轮未选 | 保留 UNMEASURED，沿既有跨域协议另行检验 |

判定沿用原规程：

- **SUPPORTED**：选测维度中至少两个必选维度有足够观察支持，且没有系统性净负效果。
- **MIXED**：不同维度方向不一致，或存在实质收益与维护成本取舍。
- **UNSUPPORTED**：足够评价后，预声明收益未获支持或出现系统性净负效果。
- **UNMEASURED**：证据、覆盖或程序条件不足。

一次真实“预测—观察—修订”只证明具备评价条件。现有预注册已签收，当前文档状态仍为 UNMEASURED；后续结论必须依据实际证据窗口更新。

### 9.3 本地好用度

沿用[好用度客观记账契约](./usability-ledger-design.md)：

- 比较滚动 28 天与前一个 28 天，每个窗口至少 20 个会话；不足时为 INSUFFICIENT_DATA。
- 六项指标：用户轮次中位数、工具错误率、重复用户消息率、大段粘贴率、首响应时延中位数、跨会话重复错误。
- 至少四项改善 ≥10% 且无一项退化 ≥10% 时为 BETTER；镜像为 WORSE；其余为 MIXED。
- 记录只保留允许的客观字段，留在本地。定义、版本与窗口按既有规程冻结，改变规则需新版本。

这些是可观察摩擦的代理指标。更少消息、日志或工具调用不能单独证明任务更好，也不能替代认知效力结论。

### 9.4 质量与控制门槛

- 不宣称未完成或未核实的工作已经完成。
- 未授权的高风险动作不执行；拒绝与停止能控制后续执行。
- 重启、重连和回执丢失不会造成重复副作用。
- 受管理的恢复不覆盖后续工作。
- 密钥、私有认知和原始会话不进入公共发布集。
- 理论候选、实现入口、身份元数据和运行事实分别核实。
- 维护成本按既有规程记录并回授，不因机制复杂就默认具有价值。

上述约束是验收条件，不是对现有实现的零缺陷声明。

## 10. 交付阶段与准入

| 阶段 | 交付结果 | 出口 |
| --- | --- | --- |
| M0 · 绑定当前基线 | 列明产品、实例、认知、模型与引擎版本；需求与已有能力对应 | 来源、所有权、支持范围和未验证项明确 |
| M1 · 日常工作闭合 | 配置、真实任务、结果核实、停止、审批、恢复和跨会话继续 | 对应 P0 真实桌面路径验收通过 |
| M2 · 认知参与工作 | 真实证据形成候选，主人裁决，正确编译加载并参与后续任务 | 认知各环节和失败恢复有独立证据，能纠正旧认知 |
| M3 · 受控试用 | 支持矩阵、治理边界、数据记录与评价入口就绪 | G1 通过，开始或继续既有证据窗口 |
| M4 · 效力结算 | 按已签收规程评价收益、复发与维护成本 | 给出有证据的效力结论，决定修订、扩展或保留现状 |

按依赖与验收推进，不在缺少工作量估算时承诺日期。

**G1 · 功能交付与受控试用准入：** P0 的声明支持范围通过真实路径验收，治理和数据边界符合要求，评价规程与记录链可运行，已知限制明确。效力尚为 UNMEASURED 时，可以进入如实标记的受控试用。

**G2 · 认知效力结算：** 按既有预注册积累和评价足够观察。SUPPORTED 才支持所声明范围内的有效性主张；MIXED、UNSUPPORTED 和 UNMEASURED 分别保留，不用功能通过或上线状态替换。

G1 完成属于阶段交付；长期目标与尚未获得证据支持的收益继续保留。

## 11. 产品验收用例

业务验收使用正在进行的真实任务。故障注入和合成夹具可以验证技术契约，其结果单独标记，不计作真实认知效力样本。

| 编号 | 场景 | 必须观察到的结果 | 对应需求 |
| --- | --- | --- | --- |
| A01 | 桌面配置与真实消息 | 选择、显示与实际模型一致；收到真实响应；失败有恢复动作 | F01/F08 |
| A02 | 真实多步任务 | 目标与约束持续保留，产物可打开，完成结论有依据 | F02/F05 |
| A03 | 多个未完成事项 | 下一步选择有目标、依赖和证据依据；实质价值冲突不擅自裁定 | F02 |
| A04 | 跨日与重启续接 | 恢复未完成工作与预期，核对陈旧事实，不要求重贴已有背景 | F03/F08 |
| A05 | 回执丢失与重连 | 核对是否已执行，不重复产生副作用，输入受到保护 | F03/F04 |
| A06 | 停止与拒绝 | 后续动作被阻止，已发生改动和无法确认的部分明确 | F04 |
| A07 | 文件撤销与冲突 | 支持恢复的改动可恢复，存在后续编辑时不强行覆盖 | F05 |
| A08 | 认知产生与采纳 | 来源、范围、失效条件可查，提案、写入、编译与使用分别可核实 | F06/F07 |
| A09 | 否决与纠正 | 否决不生效，旧认知被正确替代，后续任务使用有效版本 | F06/F07 |
| A10 | 人的反应进入证据 | 中断、拒绝、撤销保留上下文并正确分类，不自动推导成命题为假 | F04/F06 |
| A11 | 健康与认知异常 | 缺失、陈旧、损坏和读取失败可区分，不编造正常或学习成果 | F04/F07 |
| A12 | 声明支持的模型或引擎切换 | 实际身份、目标、认知与治理连续性有真实证据；未验证组合如实标记 | F08 |
| A13 | 恢复与卸载预览 | 恢复报告可核实；组件清单与私有资产分开，不越过所有权边界 | F01 |
| A14 | 效果与发布边界 | 效力与摩擦分别报告；样本不足状态正确；公共包不含私有内容 | F09 |

验收记录至少包括版本、配置范围、真实或模拟路径、输入目标、实际结果、证据位置、结论和限制。未通过项保留原因与恢复条件，不通过修改完成定义消除失败。

## 12. 风险与设计决策

| 风险 | 产品决策 |
| --- | --- |
| 已有功能多，但关键链路未进入真实工作 | 优先接通跨会话与认知闭环；实现入口不作为验收结果 |
| 旧状态或二手摘要驱动错误行动 | 保留来源、时间和可恢复指针，对高影响状态按需核验 |
| 把一次要求、人物判断或推断持久化为规律 | 区分语义类型、范围和证据，候选到生效经治理 |
| 学习维护成为新的工作负担 | AI 承担记录与推进，效果和维护成本共同评价 |
| 定时运行产生“学习成功”的错觉 | 维护调度与认知触发分开，证据不足时可以没有新提案 |
| 元数据或测试通过被解释成运行成功 | 身份、绑定、加载、真实执行和效力分别取证 |
| 跨项目或公私平面污染 | 沿既有 Adapter、脱敏和同步链，不新增隐式传播通道 |
| MVP 被用来删减长期目标或重复建设 | 保留长期目标与既有能力，只收敛本轮增量和验证范围 |
| 两套评价规则互相替代 | 认知效力与客观摩擦独立报告，变更走各自版本治理 |
