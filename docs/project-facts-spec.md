# Project Facts 规范：项目物理事实的准入与验证协议

> **定位**：取代形而上学的“因果世界模型”，用**可被机械验证的确定性事实（Project Facts）**为 Agent 提供定位、验证与避坑底座。
> **核心原则**：不可机械验证的，一律不进；不能改变行为的，一律不写；超出事实范围的判断权，恒归主人。

---

## 一、 为什么抛弃“前向推演”，改用“项目物理事实”？

1. **推演无成本，必然产生幻觉**：LLM 的“脑内前向推演”缺乏物理阻力，容易产生自信但错误的预测；
2. **配置缺失不能论证推演引擎**：历史上 90% 的所谓“因果死锁”，本质只是分级表或配置少了一行静态映射；
3. **判定者与执行者不得合一**：Agent 自主定义所谓“主线白名单”自证恒真，纯属形式主义；
4. **极简胜过宏大叙事**：一份维护良好的 60 行 `AGENTS.md` + 退出码传感器，其稳定性远超 1.4 万行认知代码。

---

## 二、 允许进入持久层的三类事实（三行表定义）

任何被持久化沉淀的知识，必须且只能属于以下三类之一：

| 分类 | 事实定义 | 唯一合法的机械验证方式 | 落地承载物 |
|---|---|---|---|
| **1. 拓扑事实 (Topology)** | 真实的入口文件、组装根、模块依赖与数据流向 | **文件系统 Glob 必须真实命中**。<br>路径一旦不存在，地图立即报警失效。 | `AGENTS.md` / `README.md` |
| **2. 传感器事实 (Sensors)** | 判定系统当前状态是否“真通过”的客观判据 | **退出码必须为 0 (`exit code == 0`)**。<br>只认退出码，零采纳口头道歉。 | `AGENTS.md` 中的 9 条合入门禁 |
| **3. 禁忌事实 (Taboos)** | 会导致数据丢失、环境破坏或死锁的确定性毒药 | **必须具备真实事故记录与 Commit SHA**。<br>严禁凭空脑补抽象禁忌。 | `FAILURES.md` (只追加，一行一条) |

---

## 三、 三大准入与淘汰硬红线（防腐败机制）

为防止认知库再次膨胀为无用的“垃圾备忘录”，执行以下机械淘汰律：

1. **不可验证律（No Unverifiable Claim）**：
   一条陈述若不能被写成：
   - `文件存在 (Test-Path / Glob)`
   - `命令退码为 0 (exit code == 0)`
   - `某年某月某日 commit X 产生过严重事故`

   则一律视为**主观观点或推测**，严禁进入持久层。

2. **定期年检淘汰律（Manual Pruning by Annual Review）**：
   不引入任何自动引用计数机制（拒绝为此增加复杂代码）。每年由主人人工过审一次，凡是环境已变迁、上游已彻底修复或架构重构后不再适用的条目，直接人工删除。

3. **零影响剔除律（No-Op Eviction）**：
   一条事实在被写入或修改后，若对 Agent 的文件改动范围、测试执行或命令选择**未产生任何实质性行为约束**，证明其为废话，立即删除。

---

## 四、 极简工程载体与日常分工

本规范不需要任何新增 Python 算法或复杂后台，全量依托已有基础设施：

- **系统骨架与传感器**：统一收敛在 [`AGENTS.md`](../AGENTS.md)（人机共读，Git 追踪）；
- **重大人祸与禁忌**：统一追加在 [`FAILURES.md`](../FAILURES.md)（纯文本，5 列固定表格）；
- **执行宿主断路器**：保留对危险操作的 `falsifier` 要求，以及完成判定前对传感器退出码的强制核验。
