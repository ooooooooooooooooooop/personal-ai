## 1. 背景与问题定义

用户对当前前端的直接评价是“太 low”。本次升级需要同时改善三个方面：

- **观感**：字体、间距、颜色、图标、控件和页面布局形成统一的视觉语言。
- **使用**：用户容易开始任务、理解执行状态、找到结果、继续之前的工作。
- **产品感**：把日常操作组织成完整流程，让高级能力在需要时出现。

公开仓快照显示，当前界面已有历史对话、搜索、文件变更与产物、设置、模型选择、后台任务和 AI 引擎管理等入口；CSS 也已有深浅主题、设计变量，并明确写了 Linear/Raycast 风格。以上证明已有前端基础，但不能证明实际渲染效果和使用体验达到了目标。[现有页面源码](https://github.com/ooooooooooooooooooop/personal-ai/blob/main/app/ui/index.html)、[现有样式源码](https://github.com/ooooooooooooooooooop/personal-ai/blob/main/app/ui/style.css)。

因此，本次设计需要验证的关键假设是：

> 统一页面结构、减少默认信息负担、改善内容阅读与执行反馈，可以显著提升界面的精致感和日常可用性。

本轮未取得本机实际运行截图，关于具体视觉缺陷的判断暂为假设。实施前必须补齐同一组场景的现状截图，作为改版基线。

## 2. 产品定位与 MVP 目标

Personal AI 面向个人持续使用，承接讨论、研究、规划和执行，并让用户能够找回上下文、查看产物、理解 AI 的行动状态。

前端升级围绕一条最短使用链展开：

**打开应用 → 开始或继续任务 → 看懂执行过程 → 必要时介入 → 查看与使用结果。**

MVP 完成后，用户应能自然回答五个问题：

1. 我现在在哪个对话、哪个工作目录？
2. 我从哪里开始？
3. AI 正在做什么，需要我处理什么？
4. 结果在哪里？
5. 我明天回来怎么接着做？

本次验收评价界面与使用体验。长期认知、学习能力和任务效果，需要各自独立的证据。

| P0 | 应用框架与侧栏 | 统一导航层级、对话列表、选中态、折叠态和连接状态 |
| P0 | 主对话工作区 | 覆盖空状态、长对话、运行中、待确认、完成、失败 |
| P0 | 输入区 | 明确发送、停止、追加指示、附件、模型和执行模式的关系 |
| P0 | 文件变更与产物页 | 易于找到结果、识别状态、查看详情并执行已有操作 |
| P0 | 设置与引擎切换 | 设置分组清楚，切换过程有真实反馈，失败可理解 |
| P0 | 统一视觉规范 | 颜色、字体、间距、圆角、图标和组件状态一致 |
| P1 | 命令面板 | 在主流程稳定后，再集中快捷操作与导航 |
| P1 | 更丰富的上下文展示 | 仅在真实数据接口和产品用途明确后加入 |

本次不包含新增长期记忆编辑器、认知图谱、插件市场、复杂仪表盘、移动端和账户体系，也不以此为由迁移前端框架。

## 6. 信息架构与页面布局

默认界面采用“侧栏 + 主工作区”，详情面板按需打开。

~~~text
┌────────────────────────────────────────────────────────────────────┐
│ Personal AI      当前对话 / 工作目录              引擎状态  详情入口 │
├───────────────┬────────────────────────────────────────────────────┤
│ ＋ 新建对话   │                                                    │
│ 搜索历史      │               对话与任务内容                       │
│               │                                                    │
│ 最近对话      │    用户需求                                        │
│  当前对话     │    AI 回复                                         │
│  其他对话     │    执行过程摘要 / 待确认操作                         │
│               │    结果与产物入口                                  │
│               │                                                    │
│ 文件与产物    │                                                    │
│ 设置          ├────────────────────────────────────────────────────┤
│ 高级 ▾        │ 输入需求……                                         │
│               │ 附件   模型 / 模式 / 更多                 发送/停止 │
│ 连接状态      │                                                    │
└───────────────┴────────────────────────────────────────────────────┘
~~~

布局要求：

- 以 1440 × 900 为主设计尺寸。
- 侧栏初始宽度约 240px，支持折叠。
- 对话内容宽度控制在约 720–840px，避免超宽阅读。
- 详情面板宽约 320–400px，打开后优先保持正文可读。
- 1024px 宽窗口下，详情使用覆盖式抽屉；更窄时侧栏也进入抽屉。
- 顶栏显示当前位置与必要状态，低频操作放入菜单。
- 高级监控保留可达入口，默认折叠。
- 各区域有明确的滚动责任，输入框始终可见。

以上数值为设计起点，需以中文长内容、窗口缩放和实际截图调整。

## 7. 核心页面与交互要求

### 7.1 新对话

页面包含欢迎语、当前工作目录、输入区和最多三个建议入口。

建议入口覆盖讨论、资料整理和行动规划，例如：

- 帮我梳理一个问题。
- 整理这份资料。
- 推进一个任务。

点击建议后将内容填入输入框，由用户发送。已有使用记录时，提供“继续最近对话”的直接入口。

模型服务未连接时，在同一工作区展示简洁的连接引导，说明当前缺少什么、下一步怎么做。

### 7.2 对话与执行

对话页明确区分三类内容：

- 用户输入。
- AI 回复。
- 工具执行与状态事件。

长回复提供清晰的段落、列表、引用、表格和代码样式。工具过程默认展示简短摘要，允许展开原始详情。

执行期间：

- 显示当前活动和已经持续的时间。
- 停止操作保持可见。
- 允许追加指示时，说明它将作用于当前运行。
- 用户向上阅读后，新增内容不强制把页面拉到底部。
- 出现新内容时提供“回到最新”入口。
- 完成后突出结果与产物入口。

### 7.3 输入区

默认露出输入框、附件入口、发送或停止按钮，以及紧凑的模型与模式入口。推理强度、用量分解等低频项进入展开菜单。

要求：

- 输入框随内容增长，到达上限后内部滚动。
- 支持中文输入法；组合输入期间按 Enter 不误发送。
- 支持 Enter 发送、Shift+Enter 换行。
- 未发送内容在页面切换时保留。
- 发送失败保留原文，并提供明确的重试入口。
- 图标按钮有可访问名称，悬停说明作为补充。

### 7.4 文件变更与产物

保留现有“文件变更回执”和“导出产物”能力，统一为容易浏览的列表与详情。

列表优先显示：

- 文件名。
- 类型或操作。
- 所属对话或任务，若数据可用。
- 状态。
- 更新时间。
- 主要操作。

长路径在详情中完整展示。打开、导出、回滚等操作沿用已有权限与服务端校验。

空状态说明产物如何出现；加载失败说明失败发生在哪里，并保留重试入口。具有相似外观的文件、目录和回执需要可区分。

### 7.5 设置与引擎

设置分为外观、模型服务、工作目录和高级设置。敏感字段沿用现有保护方式。

用户界面使用“AI 引擎”表达可切换的执行方式。切换时展示当前引擎、目标引擎和真实进度。

已有会话的切换必须沿用现有 handoff 流程。切换失败时，显示当前实际可用状态和恢复入口；前端不能提前显示成功。

## 8. 视觉规范

| 项目 | MVP 规格 |
|---|---|
| 色彩 | 中性灰构成主要界面，单一品牌色突出关键操作 |
| 深色起点 | 页面背景约 #151619，侧栏约 #111215，浮层约 #1D1F24 |
| 浅色起点 | 页面背景约 #F7F7F5，内容面约 #FFFFFF |
| 字体 | 优先系统字体，中文使用稳定的系统回退 |
| 正文 | 约 15px，行高约 1.65 |
| 控件与列表 | 13–14px；辅助信息原则上不小于 12px |
| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 32px 尺度 |
| 圆角 | 控件约 8px，卡片约 12px，弹层约 16px |
| 图标 | 沿用一致的图标体系，统一尺寸、线宽与对齐 |
| 阴影 | 主要用于浮层和层级提示 |
| 动效 | 常规反馈约 120–180ms，支持减少动态效果 |
| 状态 | 图标、文字与颜色共同表达，避免仅靠颜色区分 |

颜色是候选值，交付前需在实际组合上检测对比度。正文目标达到 4.5:1，关键控件与状态边界目标达到 3:1。

设计评审检查重点：

- 同一级元素是否使用同一套尺寸与间距。
- 中文标题、英文模型名、数字和路径混排是否整齐。
- hover、focus、active、disabled 是否完整。
- 长文本、空内容和异常状态是否仍然成立。
- 所有页面是否使用同一套组件语言。

## 9. 状态设计

| 状态 | 用户看到什么 | 可执行操作 |
|---|---|---|
| 连接中 | 连接提示；等待较长时出现恢复说明 | 查看原因或重试 |
| 可以开始 | 输入区可用，当前位置清楚 | 输入、发送 |
| 正在运行 | 当前活动、持续时间和过程摘要 | 停止、按能力追加指示 |
| 等待确认 | 待执行动作、作用对象和影响范围 | 批准、拒绝、修改 |
| 已完成 | 结果、产物及后续入口 | 查看、复制、继续讨论 |
| 执行失败 | 可理解的原因与可展开的原始错误 | 重试或调整输入 |
| 正在切换引擎 | 当前与目标引擎、真实切换阶段 | 按现有能力取消或等待 |
| 连接中断 | 连接状态和内容恢复情况 | 重连、查看详情 |

这些是界面表达状态，需要映射到现有真实事件。同一时刻只展示一个主要状态，辅助信息避免重复。

## 10. 验收标准

以下均为 MVP 目标，尚未测量。

| 维度 | 验收要求 |
|---|---|
| 观感改善 | 用相同内容、相同尺寸的改版前后截图评审；至少 5 名目标用户试用，精致度评分中位数达到 4/5，且较基线提升至少 1 分 |
| 找到入口 | 至少 4/5 用户能在 10 秒内找到新建对话、历史对话和产物入口 |
| 理解状态 | 至少 4/5 用户能正确区分运行中、等待确认、失败和完成 |
| 完成任务 | 5 名用户各执行 5 个固定任务，至少完成 23/25 次；记录阻塞原因 |
| 效率 | 固定任务的中位操作耗时较基线下降至少 20%，同时没有误操作增加 |
| 布局 | 1440×900、1280×800、1024×768 下，关键操作可见，无非预期横向溢出 |
| 缩放 | Windows 125% 与 150% 显示缩放、页面文字放大场景下，关键内容可操作 |
| 键盘操作 | 核心流程可用键盘完成；弹层可关闭，关闭后焦点返回合理位置 |
| 内容韧性 | 中文长文、长路径、代码块、表格和长对话不破坏布局 |
| 行为保持 | 发送、停止、待确认、产物访问和引擎切换保持真实行为 |

五个固定任务：

1. 新建对话并提出需求。
2. 找到旧对话并继续。
3. 理解一次运行状态并停止。
4. 找到并打开产物。
5. 完成一次引擎切换，理解失败反馈。

视觉评分、任务测试和行为回归分别记录。任何单项通过都不能代替整体体验验收。

## 11. 交付与实施顺序

| 阶段 | 交付物 | 通过条件 |
|---|---|---|
| A：建立基线 | 现状截图、五个固定任务的操作记录、问题清单 | 每个设计动作能够对应一个具体问题 |
| B：探索方向 | 深色与暖白两版主工作区候选图 | 用同样的内容比较，选出一个方向 |
| C：固定规格 | 三个核心页面、关键状态、组件与设计变量、可点击原型 | 用户能走通完整使用链，关键行为无歧义 |
| D：实现与验收 | 接入现有前端的页面、真实截图、任务测试与回归记录 | 达到第 10 节标准及仓库发布门禁 |

开发影响范围预计集中于 app/ui/ 及相关 UI 测试。保持现有 HTTP/SSE、引擎切换、授权和状态契约；生成式设计工具输出先经过适配核对。

实现时运行 app 的测试与 lint，覆盖离屏 Electron DOM 和可访问性检查；合并前执行仓库规定的完整门禁。测试继续使用环境隔离入口。
